# Atlas：lazy の例外後の再試行と、深さを制限した再入

この教材で分かるのは、初期化関数が失敗した次のアクセスと、初期化中に同じ Lazy を読む操作の違いです。例外後の再試行は公開規則へ戻り、再入の返却差は Kotlin 2.4.10 の固定 JVM 実装に限定して比べます。

Atlas の到達点は、例外と資料取得失敗を分ける、初期化済みかを読む、呼出し番号と生成順を分ける、内側/外側の役割を追う、`===` と値の一致を分ける、未検証範囲を判断する、の6点です。

## Atlas の読む順

1. [実行前契約](CONTRACT.md)と[手計算](HAND_TRACE.md)から予想する。
2. [画面](index.html)で6条件を選び、4時点を前後へ進める。画面は保存結果を読むだけです。

4. 最後の時点で予想と答えを比べ、[確認範囲](COVERAGE.md)へ戻る。

現時点の実測・画面・独立受入は [status.json](status.json) が示します。実測前は測定結果がなく、予想を観測値として表示しません。

## Atlas の比較で誤解しない点

- 例外は初回だけ意図して投げます。次の読取りで成功し、さらに読むと同じ参照になる、という単一threadの対照です。
- 再入は外側call1→内側call2。Tokenを作る順番は2→1です。番号1が先に生成されたという意味ではありません。
- 外側のinitializerがToken1を返しても、getterがToken1を返すとは限りません。PUBLICATIONの公開箇所を読み分けます。
- 再入中の非公開cacheを直接観測していません。返却値・`isInitialized()`・参照比較と固定実装を組み合わせています。
- 深さ3へ進む場合は専用guardで停止します。無制限再帰やStackOverflowは実験しません。

共有元・旧教材・旧受入は変更しません。正式Authority分類、元repository統合、全分野の完成、一般的なAgent評価はこの単元の局所確認に含みません。

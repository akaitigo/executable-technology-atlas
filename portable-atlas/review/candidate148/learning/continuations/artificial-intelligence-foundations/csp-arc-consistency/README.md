# Atlas：候補が残ることと、解があること

FCが新しい割当の隣だけを調べるのに対し、AC-3は候補の変化を未割当変数間へ伝えます。一方、AC-3を終えて全候補が非空でも、全体の解があるとは限りません。4変数2色でこの二つの境界を比べます。

読む順は[前提](PREREQUISITES.md)→[予想と操作画面](index.html)→[手計算](HAND_TRACE.md)→[原典・実装](reference.html)→[限定Skill](SKILL.md)です。現在の実施状況は[status](status.json)へ。保存結果のない段階では手表とコードだけを読み、画面に架空の測定値を表示しません。

| 条件 | 予想する問い |
|---|---|
| 鎖・A=0 | Aの制約はどこまで伝わるか |
| 三角・A=0 | B/Cの候補が残った後、どこで矛盾が見えるか |
| 三角・固定なし | 全arcにsupportがあれば解はあるか |
| 四角・固定なし | 三角と同じdomainでも、全解は同じか |

FCとAC-3は同じ入力の別copyから始めます。A:[0]は入力の固定制約です。AC-3の矢印はtail値のsupportをhead候補から探す向きで、探索の移動やassignmentではありません。全解集合は[実装前の期待](expected.json)と照合する別の情報です。

## 限界と判断

固定順FIFO、不等号、4入力だけです。三角A=0ではBCを再追加しますが、その前のCBで空になり、BC再popは未実施です。GAC、任意queue順の定理、動的探索・復元、任意入力拒否、速さの優位は今回の実測範囲にしません。前作FCの探索/復元や177既受入の成果を作り直して数えません。[範囲](COVERAGE.md)へ。

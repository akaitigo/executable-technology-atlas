本文がJSONとして完結していても、Content-Lengthが示す長さに届いていなければ、応答は未完了です。長さを指定した read が例外を出さないことと、完全に受信したことを分けます。

この画面は、ローカルHTTPで受信して保存した記録を選んで読む reader です。ボタン操作でHTTP実験を再実行しません。図は受信した数値の説明図で、パケットの撮影ではありません。実施状態は下の確認状態へ進んでください。

    4 · 原典と実装へ戻る
    RFC 9112の固定Content-Lengthの規則と、Pythonのread(amt)の振る舞いを分けて読みます。今回の実import版は実行記録のSHAで識別します。固定版では宣言長不足時に IncompleteRead を出す read(None) は、今回実測していません。

    5 · 答えと、実務での判断
    「受信できたJSON」と「完全な応答」は別です。未完了の応答から業務結果や再送の安全性は決められません。本文の上限は利用側の規約であり、完全受信の規則とは別に検査します。

# Atlas — 固定sampleのcoverageと色の集約

## 学ぶ問い

同じpixelの中心が面の外でも、一部のsampleは面の内側になり得ます。逆に中心が面の内側でも、すべてのsampleを覆うとは限りません。面への所属（coverage）、各sampleに残す面を選ぶdepth test、その色をpixelへ集約するresolveを分けて読みます。

これは2×2 pixel、5scene、2配置の有限な有理数模型です。実GPU・API・shader・MSAA品質・性能の測定ではありません。模型実行は独立期待・実行前レビューと、その回専用の資源枠の後だけです。

## 座標とsample

- xは右、yは下。pixelは行優先で (0,0),(1,0),(0,1),(1,1)。
- `center` は各pixel内 (1/2,1/2) の1点。
- `four` は (1/4,1/4),(3/4,1/4),(1/4,3/4),(3/4,3/4) の4点。この順を左上・右上・左下・右下と呼び、maskの文字順も同じです。
- 三角形の頂点は正の符号付き面積で固定します。辺 a→b の値は `(b.x-a.x)*(p.y-a.y)-(b.y-a.y)*(p.x-a.x)`。正なら内側、0なら上向き辺または右向き水平辺だけを含めます。これが本教材のtop-left規約です。
- 負の辺値、または除外する辺上では非coverageです。sampleだけを調べ、pixel面積の積分やclip処理を実行しません。

## 色・深度・描画

背景の色は (0,0,0)、初期深度は1、面のないsampleのwinnerはnullです。面色はA=(1,0,0)、B/C=(0,0,1)。色は独自の無次元RGB成分で、sRGBや表示装置の線形光を測った値ではありません。

深度zは投影後に正規化された0〜1の固定有理数で、小さい方が手前です。各面の全sampleで同じzを使い、補間・量子化はしません。coverageのときだけ `incoming_z < stored_z` を比較します。同値なら先に残った面を維持します。非coverageではdepth test未到達、`tested_depth` と `accepted` はnullです。拒否falseとは分けます。

描画前と各面の描画後に、全sampleのwinner・depth・色を保存します。resolveは全sampleの最終色を成分ごとに足し、配置のsample総数1または4で割る算術平均です。背景も分母に含みます。覆われた点数だけで割りません。各描画後の色も同じ規約で集約します。resolved depthは作らず、sample別の値を残します。

## 固定5scene

| ID | 頂点と順序 | 目的 |
|---|---|---|
| edge-low | A=(0,0),(2,0),(0,2)、z=1/2 | 中心が外でも四点中1点が内側になる |
| edge-high | A=(0,0),(5/2,0),(0,5/2)、z=1/2 | 中心が内でも四点中3点だけが内側になる |
| overlap-ab | Aはedge-low、z=1/4。B=(-1,-1),(7,-1),(-1,7)、z=3/4。A→B | 全sampleを覆う奥のBと、部分的に覆う手前のA |
| overlap-ba | 同じA/BをB→A | coverageを保ったまま順序を反転する |
| shared-edge | Aはedge-low、z=1/2。C=(2,0),(2,2),(0,2)、z=1/2。A→C | 辺上sampleをCだけへ割り当て、穴・二重所属を作らない |

同じpixel位置のcenterとfourを比較します。5scene×2配置×4pixel=40結果、最終sample100個です。全160回の面とsampleの所属判断、そのうち94回のdepth比較を予定します。単一sample規則そのもの、共有辺の一般論、量子化による同値化は既存教材を前提として再利用します。

## 手期待と別方式の検査

`hand-oracle.json` は実装前の文字列mask・採用mask・winner・depth・集約RGBを固定します。手計算は辺関数を実行せず、Aの `x+y<2`、移動したAの `x+y<5/2`、Cの `x+y>=2` と2×2内の位置から求めます。Bはこの有限点すべてを覆います。正解をproducerの計算結果から作りません。

計算の実装は辺の外積とFractionを使います。保存結果の検査は手表のmaskから段階ごとの保存値を別に組み立て、面の包含関数を再利用しません。独立担当の期待も、実装を読む前に別保存します。画面用のEXPECTEDは保存結果の破損検査用であり、独立数学期待とは呼びません。

## 入力と拒否

公開模型の入口は固定fixtureとscene ID・配置IDです。この教材の固定値・構造・実型と完全一致する入力だけを受けます。boolをintとみなさず、数値文字列は既約Fractionの標準表記に固定します。未知ID、欠落・余分なキー、範囲外/未約分/不正有理数、頂点や順序・RGB・sample位置の改変は、sample生成・coverage判断より前に拒否します。汎用rasterizerの入力域を保証しません。

不正な保存結果、欠落、別条件の記録は、表示済みの結果・答え・開いた詳細を消して拒否する画面を用意します。模型の入力拒否と、保存記録の読取拒否を区別します。

## 読み取れることと限界

maskの1の割合は固定点の所属率です。真の面積率ではなく、4点に増やせば常に良いという保証もありません。例としてedge-lowのpixel(1,0)の幾何学的な面積は1/2ですが、この配置の所属率は1/4です。

Microsoftの原典は複数位置でのcoverage/depthとsample位置・再構成処理が実装に依存する点の根拠です。今回の位置、RGB値、算術平均、図の色変換は独自規約です。texture aliasing、sample shading、透過、色空間、全形状・全将来位置、実GPUの品質や互換性は未検証です。画面の色チップは数値を読む補助で、数値表を根拠にします。

この文書は実装前の契約として固定します。計算・画面・独立受入の現在状態はstatus.jsonへ分けます。

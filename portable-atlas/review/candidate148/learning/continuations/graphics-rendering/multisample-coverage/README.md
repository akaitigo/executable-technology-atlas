# Atlas — pixelの中心だけでは見えない境界

斜めの面がpixelを横切っています。中心は面の外ですが、左上のsampleは内側です。このpixelを背景だけにするか、一部に面の色を残すかは、どの位置を調べ、どう色を集約するかで変わります。

[説明画面](index.html)では、先に予想を選び、中心1点と固定4点の保存計算を比べます。coverageは「位置が面に属するか」、depth testは「その位置にどの面を残すか」、resolveは「sampleの色を一つのpixel色へ集めること」です。三つを同じ処理だと考えず、図と表を順に追ってください。

固定5条件の計算を1回保存し、手表による照合と画面への接続を終えました。[計算結果と再現](CLI-RESULTS.md)に実行証拠をまとめています。同じブラウザーページで有限条件の表示・操作・資料導線を確認しました。[画面の確認範囲](GUI-QA.md)に、DOMの全値照合と実画像で読んだ範囲を分けて残しています。最終的な独立受入の状態は[status.json](status.json)を参照してください。CONTRACT・COVERAGEは実装前に固定した版を保持しており、その時点の状態説明と現在の状態を分けています。

## 予想から比較へ

1. 斜辺が通るpixel(1,0)について、中心と四点のどちらで赤いsampleが残るか予想します。
2. `edge-low`と`edge-high`を比べます。中心の所属だけで決める場合と、四点の1/4・3/4が所属する場合を読みます。背景も平均の分母に含みます。
3. `overlap-ab`と`overlap-ba`で描画順を変えます。奥の青い面が全面を覆っても、各sampleの深度比較で手前の赤を残せることを確かめます。
4. `shared-edge`を読みます。最終色が重なり条件と同じでも、coverageのmaskと深度比較の経路は異なります。
5. [原典との対応](SOURCE-MAP.md)、[実装前の契約](CONTRACT.md)、[手計算](HAND-CALCULATION.md)、[計算の実装](model.py)を読み、答えを照合します。

## 前提と実用判断

[前提を読む順](PREREQUISITES.md)は、既存の中心coverage・深度・clip・透視補間・深度量子化へ戻る入口です。[限定Skill](skills/atlas-graphics-multisample-coverage/SKILL.md)は、質問から比較条件と根拠へ案内します。既存教材を新しい原理として数え直しません。

境界pixelの色が違ったら、面の所属、sampleごとの深度、平均の分母を別々に確認します。所属しなかった点も背景として平均に含みます。四点中1点だからといって、幾何学的な面積の1/4を覆ったと断定はできません。

## 開き方と再現

画面は保存結果を読む設計です。このフォルダーで既存Pythonの `python3 -B serve.py --port 0` を使い、表示された `ATLAS_PORT` の `http://127.0.0.1:番号/` を開きます。配信自体は模型を動かしません。共有前提への相対リンクはローカルファイルでの参照で、この専用HTTP内で開けることは未確認です。

計算はPython標準ライブラリのFractionによる有限模型です。保存結果の読取検査は `python3 -B verify.py observations/calculation-20261007T044450218647Z` です。模型をimportせず、手表・別導出・保存されたstdoutや版との対応を確かめます。画面の改変拒否用EXPECTEDは保存結果の複製であり、この独立した手表の代わりではありません。新しく模型を実行する手順とは分離します。新しい実行にはその回の資源確認と単独枠、実nice10、1子・5秒上限と別回収2秒が必要で、自動再試行しません。旧教材の許可や観測は流用しません。

実GPU・MSAAの品質・textureのaliasing改善・shader回数・色管理・性能を測る教材ではありません。位置とRGB算術平均は独自規約です。画面の色は数値を読む補助で、正確な比較は分数表を根拠にします。

# Atlas：型の木を手で読む

`fn x:Int => x+1` ではΓにx:Intを加え、Var xとInt 1の型をそれぞれIntと読む。T_Addから本体Int、T_Fnから全体Int→Intを得る。型を付けるためにxへ実際の値を渡す必要はない。

高階の例ではΓ={f:Int→Int}でf(2)を調べる。関数側のdomain Intと引数のIntが一致するため本体はInt、外側関数は(Int→Int)→Intとなる。実引数fn x:Int=>x+1の型Int→Intが一致し、全体Int。注釈消去後の診断は外側Beta、内側Beta、AddIntsの3歩で3になる。

`0(1+2)` は静的には$.fnがIntと分かった時点で型拒否し、$.argをまだ調べない。診断の固定評価器も関数位置がIntのため0歩でstuckになるが、二つの拒否機構は別である。`(fn x:Int=>x)+1` は左のArrowが加算に必要なIntと合わない。

`fn x:Int => x(1)` の型判断ではΓ={x:Int}を使い、$.body.fnの型がArrowでないと分かる。通常経路は評価を呼ばない。一方、意図して行う診断比較は関数本体を実行しないためFn value・0歩で終わる。この対照は「一度値を得た」ことを「その本体も型検査済み」と読み替えないための例である。

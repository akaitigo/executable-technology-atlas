03 / EXPLAIN
Keyとindexの橋渡しを読む

      
項目Key→現在のindex→保持中のElement
仕組みの説明図です。Flutter画像や実行トレースではありません。

      
  1. ListView.builderは必要なindexから子を作ります。
  2. findChildIndexCallbackが、既存の子のKeyを現在のindexへ引き直します。
  3. 破棄されたStateを復元する機能ではありません。画面外の保持や業務データの所有は別に設計します。

      
今回の固定条件：12項目 / 幅320・高さ160 / 項目高80 / cache 0 / keep-alive要求なし。
Flutter 3.47.1・Dart 3.13.1。初期index 0/1、遠方8/9の生成はこのfixtureでの観測です。

04 / CHECK
予想と実測を照合する
答え合わせは「入替後」の予想についてです。遠方・戻る時点からは、入替後へ戻して照合します。

      
この結果を、どこまで使えるか
保持中の項目を並べ替えるには、安定Keyと現在indexの対応を組にします。破棄をまたいで必要な業務データは、子Stateの外に所有者を置く設計を検討します。
keep-alive有効時、削除・挿入、可変高さ、GlobalKey、保存・復元は未対応です。今回の固定条件をすべてのListViewへ一般化しません。

# Atlas｜今回扱うことと残る問い

今回の対象は6列×3方式の安定整列と、固定6queryの存在検索です。sortedness（key順）、permutation（要素保存）、stability（同値の元順）を区別します。[契約](CONTRACT.md)と[手期待](expected.json)は実装前に固定しました。比較/配置は模型内の回数で、実時間・割当量・CPU命令数ではありません。

実計算は6入力×3方式・8拒否例と各方式6queryを保存し、作者2,171項目・6改変拒否を確認しました。独立した保存照合は4,622関係・7改変拒否が成功しました。入力不変は3方式全体の前後を保存し、各方式がcopyを使うコードと合わせて確認しています。方式ごとのbefore/after実測を別保存したとは扱いません。18選択・57段階の実DOM、条件/予想/reset、3取得失敗と2旧応答、1280/390pxの代表3画像を確認しました。独立の表示照合は1,060関係です。関連2資料はhrefから同じページへ移動して本文を照合し、実リンククリックは未確認です。状態文の追補確認と最終受入は記録を参照してください。[状態](qa/reader-acceptance.json)を参照してください。APIの許容端点8件・key=-9/9を個別実測した試験ではなく、固定6列と明記した拒否例に限ります。9件とkey=10等は拒否例であり、全境界網羅とは別です。挿入の図は外側反復の配置完了後だけを示し、退避key/shift途中は詳細の記録へ分けます。併合の途中図は範囲部分列であり、全入力のpermutation判定を途中へ付けません。

元scope.jsonにはhash/BFS等の古い未教材記載もありますが、それらの追加受入済み教材は前提とし、新しい不足へ数えません。今回補うのは元LEARNING_PATH35/45行の安定性と準備費用です。

# Atlas｜安定整列と検索の準備費用



## 有限入力
fixture.jsonの6列だけを公開画面で選ぶ。各要素は整数keyと一意の元ID。空、単一、昇順4件、逆順4件、混在重複5件、全同値4件。元IDは同じkey内の元順を追うための印で、整列keyへ追加しない。実装APIでは最大8件、keyは-9..9の整数（bool不可）、IDは一意のASCII英大文字1文字、余分なfieldは禁止。入力は変更しない。

## 3方式
- insertion：左から未処理要素を取り、直前keyが厳密に大きい間だけ右へずらす。同値は越えない。
- merge_left：長さnをfloor(n/2)で左右に分けて再帰整列し、同値なら左から取る。長さ0/1はそのまま返す。
- merge_right：同じ分割で、同値だけ右から取る故障対照。key順や要素保存の成功を安定性の成功と読み替えない。

## 数え方
比較回数は整列判断で評価したkeyの二項比較だけ。ループ境界、ID検査、答え合わせ、コピーの比較は含めない。insertionではwhileのkey比較を真偽とも数え、indexが負で終わるときのkey比較はない。mergeでは両側が残る間のkey比較だけを数える。
移動回数はこの模型の列への配置回数。insertionの右shift1件を1、各外側反復の最終配置も同じ位置でも1。mergeの出力列への配置を1件1（比較せず残部を移す場合も含む）。入力copy、再帰slice、長さ0/1の返却、Python内部allocationは除外する。比較と移動を足して実時間やメモリ量にしない。MIT講義のswap数と今回の配置数は同じ尺度ではない。

## 検査と検索費用
sortednessはkeyの非減少。permutationはkeyとIDの組の多重集合が入力と同じ。stabilityは各keyのID列が元の相対順のまま。3判定を独立に表示する。原入力を参照するのは答え合わせ側であり、整列の比較へ元ID順を渡さない。
固定query列[0,1,2,3,4,5]を順番に各1回問う。線形検索は元入力を先頭からkey==queryで調べ、一致で終了。二分検索は半開区間[lo,hi)、初期lo=0/hi=n、mid=floor((lo+hi)/2)とする。key<queryならlo=mid+1、そうでなければhi=midへ進めて整列結果のlower-boundを求め、位置が列内なら最後の一致比較を1回数える。各queryで存在の真偽だけを比較する。同値のIDを選ぶ問題とは分ける。
検索の累計はquery prefixごとに、線形比較累計と「整列key比較の一回分＋二分検索比較累計」を並べる。整列の配置数は別欄。費用の逆転がこの6query内で起きない列もそのまま残す。空列の比較0は実時間0の意味ではない。独立した手表を先に保存し、producerをimportしない検査と照合する。

実装前のexpected.jsonを保持。全6入力×3方式の順序・3判定・比較/配置と6queryを独立照合する。入力拒否は空正常と分け、結果を返さない。保存結果の欠落/改変を拒否する。予想・条件・reset・取得失敗・旧応答で前の結果と答えが残らないreaderを用意する。GUIは今回保留でaccepted:falseを維持し、実画面の確認なしに最終受入を宣言しない。

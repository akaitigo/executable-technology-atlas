# Atlas｜SECDEDを案内する手順

このローカル教材を使い、SECDED（1ビット訂正・2ビット検出）の成立条件を学習者自身の予想と比較で説明します。自動インストールされたSkillではありません。

1. READMEの方法でreaderを開きます。保存した有限模型の計算を表示しており、実通信や実機の測定ではないと伝えます。
2. 元の4bitを1011、反転を位置6にします。答えを先に示さず、8bit側が元の情報を返すか予想してもらいます。
3. 表示後に、s=6・q=1と位置6の反転を確認します。位置8だけの誤りならs=0・q=1になる違いも比べます。
4. 元の4bitを0000、位置1・2の反転にします。8bit側の拒否と7bit側の1000への誤訂正を対照にします。「検査が0になれば元に戻ったと言えるか」と考えてもらいます。
5. 判定表と実行時Python実装を読み、復号器に元の4bitを渡していないことを確認します。元の情報との比較は教材側の答え合わせです。
6. 3・4箇所の反例を読み、検査通過や訂正という処理名が保証できる範囲を説明してもらいます。この2例を全多重誤りの一覧として扱いません。
7. 拒否後の破棄・再送は利用側の設計だと確認します。学習者が0・1・2bitの仮定、位置8の役割、二重誤りを訂正しない理由を言えれば、この単元の到達です。

予想や条件を変えた後に古い答えを参照しないでください。取得失敗時は再読込し、以前の成功表示で穴埋めしません。原典リンクは参考資料の該当節へ進むためのもので、教材の固定ビット配置はREADMEに従います。

計算と独立照合、readerの実操作21確認と実画像15枚の作者確認を完了しています。別担当の最終受入は `qa/reader-acceptance.json` の参照先で確かめます。範囲はCOVERAGEを参照し、Atlas全体や情報理論分野の完成とは表現しません。

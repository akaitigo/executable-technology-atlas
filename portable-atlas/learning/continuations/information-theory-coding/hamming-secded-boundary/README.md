# Atlas｜その「訂正」は、元に戻った？

SECDED（1ビット訂正・2ビット検出）を、7bit Hammingと比べる小さな教材です。**1bitなら戻せること、2bitなら値を返さず止めること、検査通過だけでは無誤りを保証できないこと**を、ビット列と判定表で確かめます。

このディレクトリで `python3 -B serve.py` を実行し、[教材を開きます](http://127.0.0.1:18755/)。終了は Ctrl+C。入口は [index.html](index.html) です。ブラウザーは保存したPythonの計算結果を選んで表示します。実通信・ハードウェア・ライブ復号の測定ではありません。

## 使う順番

1. 送る4bitと、反転する位置を選びます。まず「元の4bitを返す」「値を返さない」「異なる値を返す」のどれかを予想します。
2. 「保存した計算結果を表示」を押し、送信列・受信列・処理後の列を見ます。シンドロームと全体パリティも比べます。
3. 位置1・2を反転し、7bit側が別の値へ訂正するのに対し、8bit側が拒否する違いを確認します。位置8には7bit側の対応位置がありません。
4. 判定表、原典へのリンク、計算に使ったPython実装を読みます。「予想と計算結果を照合」で元の4bitに戻ったかを確かめます。
5. 保証外の3・4箇所の例を開きます。「訂正」や「検査通過」と表示されても元に戻らない例から、保証の仮定を説明してください。

条件を変えると予想・表示・答えを消します。予想だけを変えた場合は新しい予想を残し、前の計算表示・対照・答えを消します。「予想からやり直す」は条件を保ち、予想から再開します。読込失敗時は古い結果を使いません。

## ビットの配置と判断

左から位置1〜8を `p1 p2 d1 p4 d2 d3 d4 p8` とします。送る情報は `d1 d2 d3 d4`。偶数パリティを使い、位置8で全8bitの1の個数を偶数にします。

検査の対象は s1 が位置1・3・5・7、s2 が2・3・6・7、s4 が4・5・6・7。各集合のXORから `s = s1 + 2s2 + 4s4` を求めます。画面は s4・s2・s1 の順です。qは受信8bit全体のXORです。

| s | q | 処理 | 0・1・2bit反転の仮定内での意味 |
| --- | --- | --- | --- |
| 0 | 0 | 変更せず返す | 無誤り |
| 0以外 | 1 | 位置sを反転して返す | 位置1〜7の単一誤り |
| 0 | 1 | 位置8を反転して返す | 位置8の単一誤り |
| 0以外 | 0 | 訂正後の列も情報も返さない | 二重誤りの検出 |

**検査通過は、一般の無誤り保証ではありません。** 3bit以上ではこの意味付けが崩れます。q=0かつs≠0でも、一般の偶数個の多重誤りを区別し切れません。

## 保存した計算で分かったこと

4bitの全16メッセージに、異なる位置の0・1・2bit反転を加えました。[計算結果](observations/run-01/results.json)には以下の1056条件と、保証外の2例を別に保存しています。

| 方式 | 無反転 | 1bit反転 | 2bit反転 | 合計 |
| --- | --- | --- | --- | --- |
| 8bit SECDED | 16件：変更せず返す | 128件：全て回復（うち位置8は16件） | 448件：全て拒否 | 592 |
| 7bit Hamming | 16件：変更せず返す | 112件：全て回復 | 336件：全て別メッセージへ誤訂正 | 464 |

保証外の2例は、送る情報を0000に固定しています。位置1・2・3の反転では、位置8を訂正して1000を返します。位置1・2・3・8の反転では、検査を通過して1000を返します。これだけで3bit以上の全挙動を網羅したとは言えません。

受信語だけを受け取る [codec.py](codec.py) と、全符号語との距離で判断する [oracle.py](oracle.py) を分離しました。別方式の作者側照合は11,786項目、実装を読む前に期待を用意した別担当の照合は13,779関係が一致しています。8bitの全256受信語を距離で分けると、距離0が16語、距離1が128語、距離2が112語です。距離2では最近傍が4候補あり、任意の1つへ訂正しません。

[expected.json](expected.json) は計算前の手書き予想をそのまま保存しています。そこでの `runtimeObserved: false` は作成時点の履歴です。現在の実行状態は計算結果の `executionStatus` に記録されています。画面は計算結果と実行時ソースのSHA-256を確認してから表示します。

保存計算を読む画面も確認しました。既存Chromiumの実ポインター操作72回・キー操作8回で21項目が通り、幅1280/390の実画面15枚を保存・目視しました。基本6条件、保証外2例、入力の拒否と回復、予想変更・reset、取得失敗・内容不一致、古い遅延応答による上書き防止を含みます。[画面確認の記録](qa/run-2026-10-06T075745508Z/report.json)と[作者の画像確認](qa/self-visual-review.json)を残しています。これはreaderのブラウザー確認で、実通信・実機の測定ではありません。

別担当による最終受入の状態は [受入の参照先](qa/reader-acceptance.json) で確認できます。[範囲](COVERAGE.md)・[再現手順](REPRODUCE.md)・[案内手順](SKILL.md)・[一次資料](SOURCES.md)へ進めます。

## 実務での判断と限界

訂正・拒否を受けた後の利用判断と、誤り訂正符号の判定を分けます。この教材では拒否時に情報を返しません。破棄・再送・機器の障害処理は利用側の設計であり、ここには実装していません。

これは有限なビット反転模型です。実メモリーのECC配置、通信の誤り率、バースト誤り、再送、機器固有の制御、圧縮を扱いません。情報理論全体やSECDEDのあらゆる構成が完成したという意味ではありません。

copy は rb で読んだ内容を xb で新規ファイルへ書きます。書換えは r+b で先頭から同じ長さだけ行い、置換や切詰めをしません。





4. 答えと実務での判断



内容の一致だけでは、更新を共有するか判断できません。別名として使うなら hardlink の共有更新を考慮し、独立した内容を残したいならコピー後の読取りと更新の対照を確認します。バックアップの復元性や耐久性は、さらに別の検証が必要です。





5. この測定で分からないこと


物理ブロックの共有・非共有、すべての属性の独立、速さ、電源断後の永続性は測っていません。ファイルシステムの種類も特定していません。名前を消す前に開いた参照を残す実験は、既存の OS 教材で扱います。


実験準備中に sandbox で停止した記録と、link の宛先が既にあるため意図どおり失敗する EEXIST は別です。削除後の original に対する ENOENT は「名前がない」という観測です。実行状況と読み方 · 扱った範囲と残る範囲

# Atlas：hardlink と copy を学ぶ手順

1. README の 6 項目と COVERAGE の境界を読み、既存 OS 教材との重複を確認する。
2. index.html で時点と予想を選ぶ。表示は保存済みの結果を読む操作で、新しい OS 実験ではないと説明する。
3. 同じ実行の `(st_dev, st_ino)`、nlink、全バイト列を固定期待値と比べる。inode は dev と組にして扱い、番号を別実行と比較しない。
4. 正常操作、意図した EEXIST、最初の準備失敗を区別して読む。初回失敗を消さず、起動 2 回・準備失敗 1 回・ファイル実験 1 回と説明する。
5. 原典と実装を読み、答えを開く。物理ブロックの共有や電源断耐久性へ結論を広げない。
6. 保存結果の照合には `python3 -B verify.py observations/attempt-2/run.json` を使う。experiment.py は学習画面から起動しない。再実験が必要になった場合は既存記録を上書きせず、資源・専有範囲・実行許可を確認する。

画面や画像の確認が未実施なら、その状態を結果に記す。独立した受入確認と Atlas 全体の計上は担当者へ渡す。共有の旧教材・計画・台帳をこの手順で変更しない。

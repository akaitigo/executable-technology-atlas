# 疎なファイルの学習を進める

対象は、このフォルダーの教材を使ってsparse fileの基礎を理解・確認したい場面です。ファイルシステム全体や性能診断には適用しません。

1. README.mdとCOVERAGE.mdを読み、今回の範囲を「位置・論理長・読める内容・OS報告の割当量」に限定する。
2. seekだけ／末尾X書込み／同じ内容の通常書込みについて、学習者に予想と理由を書いてもらう。
3. index.htmlで予想→保存観測と対照→原典・実装→答えの順に読む。予想編集・条件変更・resetで古い結果が消えることを確認する。file-layout.svgは模式図で、保存観測の閲覧を新しい実験と呼ばない。
4. 再実行を求められたら、フォルダー内で <code>python3 -B experiment.py &gt; run-local.json</code>、続いて <code>python3 -B verify.py run-local.json</code> を使う。標準ライブラリのみ。既存観測ファイルを上書きしない。サイズ・外部パスの追加機能はこのSkillの範囲外。
5. 実行結果の先頭65535ゼロ・末尾X・EOFと論理長を、実行前のexpected.jsonに照らす。検証器は実験を再実行しない。
6. st_blocks × 512をOS報告値として説明する。疎な方が小さいことを合格条件にしない。物理予約・性能・電源断耐久性へ推論しない。
7. 予想と観測の違いを自分の言葉で答え合わせする。自由文の予想を自動採点しているとは言わない。初回GUI5検査/4画像と、現GUI15検査/7画像は履歴を分けてREADMEからたどる。現GUIは42実pointer・11文字入力と選択API6回を区別し、native dropdown手操作未確認を残す。
8. 受入はobservations/status.jsonに示す別reviewerの判断に従う。旧原票や失敗QAを成功へ書き換えない。元coverageの次課題は既存受入との重複を調整担当が確認してから選ぶ。Portal統合は未完了で、新しい単元を自動で増やさない。

実験はMac/Unixのpreadが必要です。WindowsやDockerの新規環境を用意する手順は含みません。実ブラウザツールがない場合は未検証と記録し、図を実画面captureとして扱わないでください。

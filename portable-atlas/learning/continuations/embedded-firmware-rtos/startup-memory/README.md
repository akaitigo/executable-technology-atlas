# Atlas — ROMに初期値があれば、RAMも正しいか

プログラムが使う場所と、初期値を保存する場所は同じとは限りません。この教材は16 byteずつの架空ROM/RAMで、`.data`のコピー、`.bss`のゼロ初期化、値を読み始める時点を比べます。実機の起動やlinkerの実行ではなく、Pythonで動かす有限のbyte模型です。

## 前提から読む



1. [契約](CONTRACT.md)の配置図に相当する範囲を読み、copyとzeroのどちらを先にすべきか予想します。
2. 両方の順を比べ、領域が重ならなければどちらでも同じRAMになる理由を確かめます。
3. コピー省略、ゼロ化省略、早すぎるmainを比較します。最後のRAMだけで、過去の読値が正しかったとは判断しません。
4. 1 byteの書き過ぎでは、dataとbssの値が合っていても保護用byteが壊れます。全writeと全RAMを読みます。
5. [手表](hand-oracle.json)・[原典の対応](SOURCE-MAP.md)へ戻り、予想の根拠と限界を確認します。

LMAは初期値を置く側、VMAは使う側を指す原典の用語です。本模型ではROM/RAMという領域名とoffsetに対応させます。実MMUや物理アドレス変換ではありません。A5とCCは見分けるための合成値で、実電源投入時の値を表しません。

## 到達目標と限界

配置と初期化の実行を分ける、非重複な処理に偽の順序依存を作らない、早期読取りを後の正しい状態で隠さない、空領域のwrite0を説明する、変数値だけで越境なしと判断しない、の5つを目標にします。

## 画面で読む

[画面の入口](index.html)で予想を選び、「保存した計算を開く」を押します。「前の境界」「次の境界」でRAMの変化を追い、mainの読値と全操作の書込み履歴を対照します。条件・予想・記録の種類を変えると前の結果を消します。欠落や改変のボタンは固定データの複製を変える操作で、実際の通信障害の測定ではありません。

ローカルHTTPでMarkdownを本文として読む場合は、このディレクトリで次を使います。画面の表示や保存結果の検査は模型を再計算しません。

```sh
python3 -B serve.py --port 0
```

表示された `ATLAS_PORT` の番号で `http://127.0.0.1:番号/index.html` を開きます。配信はこの教材内の静的ファイルだけです。停止は起動した端末のCtrl-Cで行います。共有ブラウザーや他のサーバーを停止する手順ではありません。

Atlas / 音声・映像の時間

丸めの積み重ねと、
時計のずれを分ける。

同じサンプル数でも、時刻への換算方法で差が生まれます。

48,000 sample/s の有限な計算を読む教材です。実際のデバイス時計・音声・再生・RTP通信は測定していません。

01 / 予想

区間ごとに丸めても、同じ時刻になる？

サンプルは音の値を数える単位。mono では1サンプルが1フレームです。サンプル0の境界を0msとし、位置 N の正確な名目時刻は N / 48 ms。整数msへ丸めるときは、ちょうど0.5を上へ丸めます。

末尾では、区間ごとの丸め加算は絶対位置からの換算より…

02 / 操作と対照

原点から換算するか、丸めた区間を足すか

ずれの原因を分ける

青は絶対位置から換算した丸め誤差、橙は区間ごとに丸めた累積誤差、紫は仮定した時計の速さの差です。すべてmsで表示します。

記録を読めないときの比較
保存記録の欠落・改変・別条件を拒否し、前の計算結果や答えを消します。デバイスの故障を起こす操作ではありません。


03 / 原典・実装
サンプル時刻は、到着した時刻とは別
RFC3550 §5.1 はサンプリング時点と時計周波数を説明しています。ここで選んだ原点0、整数ms、丸め方、+100ppm は教材の比較条件で、RFCの要求ではありません。
原典と既存教材・規約・実装前の手表・整数による実装・Fractionによる別照合


04 / 答え合わせ
小さく見える差が、補正の成功とは限らない


05 / 実務判断と限界
丸めを直しても、時計の速さは別に残る
絶対位置から換算すると、その丸め誤差は各境界で0.5ms以内です。しかし、基準時計との比較には別の時計差が加わります。+100ppm はここでは仮定値で、時計の初期ずれは0としています。
到着遅延、音質、実再生、RTPの時刻wrap、RTCP同期、可変レート、負の時計差、補正方式は未検証です。
使い方と再現・範囲と次の問い・案内の手順・現在の確認状況

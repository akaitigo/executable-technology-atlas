# Atlas：同じ一致集合でも、順位が変わる

この教材では、検索語alphaを含む文書を変えずに、語の回数と文書長を使う得点を比較します。目標67の「一致集合と順位を説明する」、既存の転置索引の教材の[次課題](SOURCE-MAP.md)を引き継ぎます。実際の検索エンジンや利用者評価ではなく、小さなPython計算です。

入口は [index.html](index.html) です。Mac のブラウザーで直接開き、予想を選んで保存した計算を比較します。計算と画面の実操作を確認済みです。1280px・390pxの表示、予想の編集・リセット・記録の拒否を確認し、7枚の実画面を保存しました。独立受入の参照は [status.json](status.json) にまとめています。

## 前提をつなぐ

文書ID、単語、集合、回数、分子と分母を使います。検索語を含むかが「一致」、同じ候補のどれを先に表示するかが「順位」です。上位に出たことと、人にとって有用なことは別の問いです。

- TFは文書内の検索語の回数です。
- dfは検索語を含む文書の数、Nは全体の文書数です。今回はN=4、df=2です。
- IDFは今回 `ln(N/df)=ln2` と固定します。lnは自然対数です。候補に共通する正の係数なので、これを外しても今回の順位は変わりません。
- 文書長は空白で区切ったトークン数、平均長は全トークン数16を空文書を含む4文書で割った4です。

対数を計算できなくても、共通IDFを外した有理数（整数の比）の表で先に比較できます。文章を単一空白で区切るだけの小文字ASCII入力で、日本語解析や単語の意味は扱いません。

## 予想 → 操作 → 比較 → 原典 → 答え

1. d1はalphaが2回・長さ8、d2は1回・長さ2と数え、先頭を予想します。d3は空、d4は検索語を含みません。
2. 方式を選び、保存した計算を開きます。まず一致集合が同じかを見ます。
3. 分子・分母、共通IDFを外した値、最終得点、表示順を分けて読みます。
4. [契約](CONTRACT.md)と[著者原典の式86](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html)、[実装](model.py)へ戻ります。
5. 答え合わせを開き、[実装前の手計算](hand-oracle.json)と照合します。同点でd1を先に表示しても、d1の得点が高いわけではありません。

| 方式 | 共通IDFを外したd1 | d2 | 手計算による予想 |
|---|---:|---:|---|
| 長さで正規化しないTF×IDF | 2 | 1 | d1が高い |
| BM25 k1=1、b=0 | 4/3 | 1 | d1が高い |
| BM25 k1=1、b=1/2 | 8/7 | 8/7 | 同点。ID順でd1→d2 |
| BM25 k1=1、b=1 | 1 | 4/3 | d2が高い |

TF×IDFではtfを対数化したり、文書長やベクトル長で割ったりしません。BM25は語の回数に対する得点の伸び方と長さの補正を持ちます。ここで選んだk1とbは対照のための固定値で、最適設定ではありません。

**IDFの式を混ぜません。** 原典式85の確率的IDFなら今回df=N/2で0です。式86の `ln(N/df)` や別形式の `ln(1+...)` は同じ数式ではありません。この教材が全検索製品の既定式に一致するとは主張しません。

非一致文書は候補外です。空文書もNと平均長の分母には含みますが、tf=0なら除算前に得点0・順位なしとし、0/0を計算しません。入力順はd2,d1,d4,d3、同点時の表示はID昇順という独自規約です。

## 検証の設計

固定入力、式の契約、手計算16行は計算処理と検査器を作る前に保存しました。計算側は浮動小数点数で得点を求め、検査側は計算処理を読み込まず、Fraction（整数の比を正確に扱う型）の表へ照合します。得点の絶対許容差は1e-12、文書集合・順位・同点・非一致分岐は完全一致とします。

[計算取得](observe.py)は4方式と13種類の入力拒否を記録し、[検査器](verify.py)は保存結果の欠落・方式混入・得点/順位など10種類の改変を検出する設計です。保存した計算では4方式・16文書行、入力拒否13件、改変検出10件が通りました。Mac/arm64、CPython 3.9.6で2026-10-06 14:55 UTCに1回実行し、計算部分は約0.0013秒、子の起動と回収を含む処理は約0.323秒でした。これは検索性能の測定ではありません。

通常の学習では保存した結果を読むだけです。新しい計算は、専用枠・新しい資源確認・同じ子でのnice10設定と実値確認が揃う場合だけ行います。初回の資源確認では既存Java候補により計算開始を止めました。特定のPID・開始時刻・実行ファイルと低いCPU使用率を読み取る限定条件を独立に確認し、新しい資源確認後に計算しました。同じ子でnice値10を確認し、5秒の観測期限と別に2秒の回収猶予を設定、再試行0・回収完了です。他のプロセスは変更していません。

## 実務判断と限界

「回数が多いから上位」を目的にしたいのか、長さを補正したいのかを式から説明します。この1語ではIDFが共通なので、語の希少性の効果一般は検証しません。順位の逆転を関連性の改善とは呼びません。

複数語、関連性の正解ラベル、precision@k、パラメーター最適化、製品互換、意味に基づく検索、日本語解析、実利用評価、性能は未確認です。[COVERAGE.md](COVERAGE.md)、[有限Skill](SKILL.md)、[画面の確認範囲](GUI-QA.md)も参照してください。

# Atlas：検索順位の範囲と残る不足

既存Boolean教材は一致集合、precision-recall-contractは指定した関連集合に対する評価を扱います。この単元はそのどちらも新規に数えず、語の頻度と文書長による得点・順位を対応付けます。

| 問い | 固定する比較 | 限界 |
|---|---|---|
| 一致集合と順位は同じものか | 同じd1/d2を4方式で並べる | 実利用者の関連性は未評価 |
| 回数を2倍にすると得点も2倍か | raw TF×IDFとBM25 b0 | tfの広い範囲の挙動や最適k1を保証しない |
| 長さの補正で何が変わるか | b0→1/2→1、順位維持→同点→逆転 | 4文書・1語だけ |
| 同点と表示順を分けられるか | 得点同一8/7、ID昇順 | 他製品のtie規約ではない |
| 空と非一致をどう扱うか | 空文書もN/avgdlに含む、tf0は除算前に候補外 | N=0/df0/all-emptyは入力拒否 |
| 計算と検査が同じ誤りを写さないか | 浮動小数点計算と固定手表・有理数を別に照合 | 一般検索エンジンの正しさではない |

実装前契約・独立手計算を固定後、4方式16行を1回のPython処理で計算しました。入力拒否13件・保存結果の改変検出10件が通り、子は回収済みです。画面は35項目・実クリック46回・キー操作1回を確認しました。全4方式16行の表示値と丸める前の記録を照合し、1280px/390pxの7画像を目視しました。状態だけの66項目確認とは別に記録しています。保存結果と検査への入口はREADMEにあります。

次の不足は複数語でdfの異なる語を比べることです。1語の今回では共通IDFが順位へ与える一般的影響を学習済みとはしません。その先のprecision@kや利用者関連性は、既存precision/recallへ戻り、別に固定した正解ラベルと順位の関係を検証する必要があります。

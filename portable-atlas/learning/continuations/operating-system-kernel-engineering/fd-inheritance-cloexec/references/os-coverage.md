# OS・kernel engineeringの道筋と未教材coverage

今回の有限1unitは実parent/childのpipe・FD参照寿命・signal・wait。user-spaceから実OSの振る舞いを観測する。OS分野全体の完成、kernel改造、内部scheduler tracing、VM実行ではない。

前提はprocess/PID、byte列、read/write/close、所有するresourceの回収。FDはprocess内の番号で、PIDを跨ぐ同じ数字が同じresourceの保証にはならない。今回はpass_fdsで渡したread-endと親のduplicate write-endを追う。主要概念を[README](README.md)→[操作UI](index.html)→[原典](SOURCES.md)→以下の次実験へ繋ぐ。

実務判断: subprocessが終了しない時、processの生存だけでなく全write-endの所有者、buffer残量、close/waitの順番を調べる。signalでprocessを止めるcleanupとprotocol正常完了を混同しない。短いtimeoutのelapsedは負荷/待ち精度に依存し、性能ランキングに使わない。

限界: このMacのPython/Darwinで最大1owned child・512ASCII bytes・100..500msのbounded wait。通常・0byte EOF・512byte境界・duplicate leak解放・SIGTERM終了の有限観測で、全OS/全kernel path/全signal/全I/Oサイズの証明ではない。monotonicは各process内だけで比較、wall timestampは表示用でclock adjustmentがあり得る。kernel改造、VM、host設定、root権限、global install、Docker、外部サービス、公開は未実施。

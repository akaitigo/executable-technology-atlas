短い仕事を先にすると、誰が待つ？

処理量が同じでも、仕事を始める順序で待ち時間は変わります。平均が改善したとき、個々の仕事も改善したのかを、時間図で確かめます。

固定された 3 仕事の有限モデルです。A は 5、B と C は 1 tick。すべて時刻 0 に到着し、1 台で、中断せずに処理します。tick は架空の時間単位で、実サーバーの秒数ではありません。

1. 予想する

FIFO は同時到着の登録順 A → B → C。短い順では B → C → A です。順序を変えたとき、長い仕事 A の完了はどうなるでしょう。

メニューのほか、前後のボタンでも6つの順序を選べます。最初と最後では、その方向のボタンが無効になります。

4. 答え合わせと判断

    

    
「平均が小さくなったので、全員が早く終わった」は、この例では誤りです。平均に加えて、誰の完了が遅れたのか、最後の完了時刻が変わったのかを確認します。3 件の最大値を、本番の p95 や p99 と呼ぶことはできません。

  

  

    
5. 限界と次の問い

    
全 6 順序で仕事数は 3、処理時間の合計は 7。今回は順序を変えても能力は増えていません。全件が必ず完了する有限入力なので、仕事が無期限に待つ starvation（飢餓）は検証していません。

    
処理時間を事前に知れないとき、到着が続くとき、期限や重みがあるとき、複数サーバーで動かすときは別の実験が必要です。実 CPU・I/O・メモリー、本番容量、負荷試験、一般的な公平性も未検証です。

    
これは 3 仕事の有限模型です。実サーバーの性能・本番容量・一般的な starvation を検証するものではありません。現行 reader の検証範囲 ／ 初回操作記録 ／ 初回目視記録。Atlas への統合は別工程です。

# Atlas — 測定と真の状態を分けて読む

[README](README.md)・[現在の状態](status.json)で、計算と画面の実施状況を確認する。未実行の手表を観測結果として説明しない。[前提](PREREQUISITES.md)から既存の比例制御・入力保持・測定統計へ戻れる。

1. 「雑音が0なら測定は今の状態か」にはcurrent-exactとdelayed-oneのk=1を比較する。参照番号0と現在番号1、m=0とx=1/2を分け、変わった入力u=1から次の状態3/4を読む。初期履歴x[−1]=0を省かない。
2. 「測定値に雑音を足すだけなら状態は変わらないか」にはfixed-noiseを案内する。測定経路へ加えた値が入力へ戻り、次の内部状態を変える。雑音を直接plantへ加えた結果とはしない。固定列を実測や確率分布の証拠にしない。
3. 「ちょうど半分をどう丸めたか」にはquantized-unitのk=1と正負9境界の表へ。+1/2→1、−1/2→−1の規約を確認し、k=1でu=0・次x=1/4となることを手表と比較する。実ADCや製品互換性へ広げない。
4. 「最後の入力は既に適用されたか」にはk=6のinput_applied=falseとnext_state=nullを確認する。k=5の適用と分け、0という計算値と未適用を混同しない。
5. 「この結果で設定や精度を保証できるか」には[COVERAGE](COVERAGE.md)と既存の測定統計へ戻す。今回の6更新・係数1/2・gain1の観察は、無限時間の安定性、校正、一般雑音耐性や実機安全性の証明ではない。baselineでも目標偏差1/2が残る。

予想→[画面](index.html)の時点操作→正常な現在値と測定経路の比較→[原典対応](SOURCE-MAP.md)・[契約](CONTRACT.md)・[手表](hand-oracle.json)・[実装](model.py)→答え→実務判断の順に進む。保存計算がまだ未接続なら、その段階を説明し、成功表を作って補わない。外部機器、SDK、設定変更や新サービスをこのSkillで開始しない。

# Atlas：因果の辺を確かめる

1. [状態](status.json)を読む。測定結果が未接続なら[契約](CONTRACT.md)・[手表](HAND_TRACE.md)・[原典](SOURCES.md)・[コード](model.py)まで案内し、予想を測定値と呼ばない。画面未確認ならその限界も示す。
2. [前提](PREREQUISITES.md)で既存のcounter/版/vector比較と今回の全対検証を分ける。[入力](inputs/events.json)でprocessと同一messageの対応を確認する。
3. [画面](index.html)の予想→条件比較→原典/実装→答え→限界を辿る。保存結果の閲覧に再計算は不要。実行ログは状態記録にある現在の参照へ進む。
4. 次の6問を、規則・手期待・保存結果・未検証に分けて案内する。
   - a→fはどの経路か。a→e→fの辺の出所を見る。
   - b2<f3なのにbとfが並行なのはなぜか。両方向の到達なしと逆推論の偽陽性を比べる。
   - aとdの時計1は同じ物理時刻か。固定ラベルの等値と時計測定の不在を分ける。
   - R2でf3の後にb2が見えてよいか。並行な組を並べ替えても15組の分類は変わらない。
   - R1を因果辺に混ぜると何が増えるか。4つの誤った向きをIDで示す。
   - この表だけで実ログの欠損やcausal consistencyを保証できるか。完全な合成入力と保証外を示す。
5. 再現時は [README](README.md) の資源・実優先度・時間・所有子回収の条件を守り、新しい保存先へ記録する。現在の対象枠なしにproducer、browser、serverを自動起動しない。資料の読取だけならそのまま続けられる。

Skill文書があることや、この6問で資料を辿れたことを、未知の質問への一般Agent評価と扱わない。元repo・共有台帳・既受入結果は更新しない。

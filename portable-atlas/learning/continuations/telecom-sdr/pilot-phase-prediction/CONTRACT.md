# Atlas — pilot から後の位相を予測する有限契約

実装前に固定する契約です。現在状態は後に status.json へ分けて記録します。無線機、実電波、MATLAB、GNU Radio は使いません。

## 問いと前提

既知の信号である pilot で位相を合わせても、後の信号まで正しく読めるとは限りません。直近の pilot の位相を保持する方法と、2 点から回転の速さを見積もって外挿する方法を比べます。ここで外挿とは、観測済みの関係が後にも続くと仮定した予測です。PLL や観測を追加して修正する追従ループは実装しません。

目標95、元 Telecom SDR の phase-drift の問いに対応します。既存の固定位相の逆回転、pilot 品質による拒否、受信窓と信号のずれは前提です。本教材では受信する時点は既知、振幅は1、雑音なしです。欠落を示す pilot の値0だけを別条件にします。品質閾値・受信窓・誤り訂正を再実装しません。

## 時点、入力、正解を持つ側

symbol は1回の信号値を指します。番号 n=0..5 は等間隔の6時点であり、秒・Hz・実時計ではありません。n=0,1 の既知 pilot はどちらも bit 0、BPSK の対応は bit 0→+1、bit 1→−1 です。n=2..5 の4個を payload と呼びます。検査側だけが正解 payload [0,1,1,0] と、模型で定めた channel の全列を持ちます。

receiver の引数は、方式名と、既知 pilot の番号/bit、受信 pilot の I/Q、payload の番号と受信 I/Q だけです。真の channel、正解 payload、条件ID、将来の回転方向を渡しません。`fixtures.json` は receiver 入力、`comparison-truth.json` は検査専用に分離します。生成した受信値は固定 fixture へ照合し、receiver はそこから渡した request だけを使います。

複素数は [I,Q] の2要素で、各成分は既約の分数字符列です。整数も文字列（例 "0"）、分母は正です。float/bool/NaN、非正規形、余分/欠けたキー、異なる番号/bit、異なる長さ、不明な方式は復調前に入力拒否とします。pilot は単位複素数または0、payload は単位複素数に限定します。これはこの有限入力の検査であり、実受信振幅の一般仕様ではありません。

## 4条件

`r=(3+4i)/5`、`P_j=r^j` とします。channel は受信値を作る検査側の設定です。

| ID | channel h[0..5] | 受信 pilot |
|---|---|---|
| constant-phase | 1,1,1,1,1,1 | 1,1 |
| constant-rate | P0,P1,P2,P3,P4,P5 | P0,P1 |
| rate-reversal | P0,P1,P2,P3,P2,P1 | P0,P1 |
| first-pilot-missing | constant-rate と同じ | 0,P1（最初だけ欠落） |

受信 payload は正解の符号 s[n] と h[n] の積です。rate-reversal は3→4以降の1区間ごとの回転が conj(r) へ変わります。位相そのものを突然0にする条件ではありません。欠落条件の0は合成した欠落表現であり、実装置の検出ではありません。

## 2方式と復調

pilot から符号を除いた値を z0,z1 とします（今回は既知 bit が両方0なので受信値と同じ）。

- `hold-latest`：z1 が非0なら、全 payload で予測 channel `h_hat[n]=z1`。z0 を推定に使わないので最初の pilot が欠落しても処理できます。
- `extrapolate-two`：両方が非0なら、`r_hat=z1*conj(z0)`、`h_hat[n]=z1*r_hat^(n−1)`。両 pilot が単位振幅・間隔1という限定に依存します。z0=0 なら `NO_FIRST_PILOT` として未推定。z1=0 なら両方式 `NO_LATEST_PILOT` として未推定です。

補正係数は `conj(h_hat[n])`、補正値は `received[n]*conj(h_hat[n])`。補正値の I<0 を bit 1、I>=0 を bit 0 とします。ちょうど0は元教材と同じ bit 0 規約です。今回の正常な固定 payload では I=0 は生じません。丸めはせず Fraction で厳密に比較します。

未推定では予測 channel/補正係数/補正値/復調bit/誤り数を null、比較 bit 数を0、誤り位置を null にします。0誤りや4個全て成功とは扱いません。入力拒否は未推定とも別で、復調行数0です。成功は処理が定義どおり完了した意味で、正解への一致とは分けます。

## 実装前期待と別経路

手表は全4条件×2方式の受信値、予測、係数、補正値、判定、比較位置を literal で固定します。候補の誤り数は順に保持/外挿で 0/0、3/0、1/2、3/未推定。独立レビューが手表を照合するまでは候補値です。

計算側は複素積の逐次更新で予測します。検査側は `r^j` の二項展開（偶数項が実部、奇数項が虚部）と、`(a+bi)*conj(c+di)=(ac+bd)+(bc−ad)i` の内積/外積を使い、計算側を import せず手表の全成分へ照合します。検査用正解は receiver の処理が返った後にだけ比較します。予測失敗を正解列で補いません。

保存値には n、受信値、推定に使った pilot 番号、予測 channel、補正係数、補正値、判定bitと、その後に行う正解比較を別欄へ残します。channel の真値を表示する場合は『検査用の設定』と明記し、受信側が観測した値とは呼びません。

## 実行・画面・限界

独立期待と実装前レビュー、今回の資源観測と単独枠の後だけ、既存 Python 標準ライブラリで小さい1子を実行します。実nice10、5秒と別回収2秒、自動再試行0。ブラウザーと配信は既存の同じページを管理する担当からの実行だけで、作者は起動しません。

画面は予想→保存した計算の操作/比較→原典と実装→答え→実務判断。条件/予想/reset/記録の欠落・改変で古い図、答え、開いた詳細を消し、正常記録で回復します。全列と選択した時点の値を区別します。

周波数差と位相累積の関係は原典へ案内しますが、ここでは1 symbolあたりの回転だけを定義します。実Hz推定、周波数の折返し識別、PLLの収束、雑音下の推定品質、実RF、実クロック、連続stream、一般BER、全ての将来の回転に対する優劣は保証しません。回転方向が途中で変わる反例では外挿が保持より悪化します。

# Atlas — pilot で合わせた位相は、後でも使えるか

既知の信号 pilot を使って向きを合わせても、後の信号が同じ向きを保つとは限りません。[学習画面](index.html)では、直近の位相を保持する方法と、2点から回転を予測する方法を比べます。これは2 pilot と、その後で判定するデータ（payload）4個の有限計算です。channelは受信信号の向きを変える係数を指します。無線機の測定や、信号を追い続けるPLLの実験ではありません。

## 先に確かめること

[前提の読む順](PREREQUISITES.md)から、bit 0→+1、bit 1→−1、I/Q、共役による逆回転を確認してください。元教材の固定位相、pilot品質の拒否、受信窓のずれは別の原因です。今回の新しい問いは「観測した回転が後にも続く」という仮定を使えるか、です。

## 予想して操作する

1. 画面で固定位相・一定回転・途中反転・最初のpilot欠落を選びます。
2. 保持と外挿のどちらの誤りが少ないか、欠落時に外挿できるかを予想します。
3. 保存した計算を開き、同じ受信値、予測したchannel、補正したI/Q、判定bitを順に比べます。n=0,1はpilot、n=2..5が比較対象です。
4. 答えを開き、誤りの位置と、推定できず比較しなかった状態を分けます。

全列は計算全体の保存結果です。時点の選択は表示の切替えで、外挿器に後の真値を教える操作ではありません。条件・予想・記録を変えたりresetしたりすると、古い答えと詳細を消します。記録の欠落/改変は画面内の保存データへの合成した故障であり、実際の通信障害や攻撃の測定ではありません。

## 再現と保存結果

[保存した計算](observations/calculation-20261007T001354443421Z/result.json)は4条件×2方式32行。未推定の4行は判定null・比較0のままです。1回の計算は実nice10、0.453秒、exit0、子の回収済み。18入力拒否、16種の変更検出を確認しました。[実行ログ](observations/calculation-20261007T001354443421Z/report.json)と[保存値の検査](observations/calculation-20261007T001354443421Z/verification.json)を分けています。

`python3 -B verify.py observations/calculation-20261007T001354443421Z` で、計算対象を再実行せず結果・入力・実行版を照合できます。画面へはこの保存結果だけを接続しました。79件の状態処理確認はDOMのない検査であり、実画面確認は別です。現在状態は [status.json](status.json) へ残します。

実行前の相対pathを組み立てる準備で1回の読取失敗があり、対象起動前に修正しました。同じ新しい資源記録の60秒以内でsource一致を確認して実行しています。[その記録](observations/preflight-path-correction.json)と初期資源条件の停止は保持し、計算の再試行とは分けています。

画面の配信は `python3 -B serve.py --port 0` が表示するポートの `http://127.0.0.1:<port>/` を使います。Markdownはテキストとして読みます。配信は計算やブラウザーを起動しません。制作中の実画面確認は既存の同じブラウザーページで行い、新規起動とは区別して記録します。

新しい計算は `run.py --record --gate <今回の資源記録>` による別の操作です。今回の独立レビュー、直前の資源確認、単独枠、実nice10、5秒と別回収2秒が必要です。古い資源記録や過去の許可を再利用しません。

## 答えから実務判断へ

一定の回転なら2点からの予測は役立ちます。しかし、その後で回転方向が変わる条件では同じ予測が外れ、保持より誤りが多くなります。「正常なpilotを受け取った」と「その後の位相モデルも正しい」は別の判断です。最初のpilot欠落では、最新値の保持はできても、2点差を使う外挿の根拠が足りません。

追加pilotで確かめる、推定を更新する、雑音下の不確かさを評価する、といった次の設計は別の検証を要します。ここでの誤り割合は4個の固定bitの比較です。実RF、Hz推定、PLLの収束、製品互換、統計的な誤り率、将来の全回転に対する優劣は保証しません。[範囲](COVERAGE.md)へ戻れます。

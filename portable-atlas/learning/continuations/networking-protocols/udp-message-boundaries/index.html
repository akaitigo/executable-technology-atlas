03 · DECIDE
受信ループの、4つの判断
  1. 空をアプリで許可・拒否する。transport EOFにしない。
  2. 最大payload長を契約にする。recv幅不足の結果を全文として処理せず、別datagramから補充しない。
  3. send成功・受信・検証・永続化・処理完了を分ける。業務ackの意味とrequest IDを決める。
  4. 配送・順序・重複・認証が必要なら、それを提供するprotocolを選ぶ。sender addressは認証にならない。
第3timeoutは追加dataを観測しなかっただけで、lossや相手EOFの証拠ではありません。空payloadにもUDP/IP headerがあります。これはAPI原票で、packet captureではありません。
範囲：127.0.0.1の4条件 / 各2socket / 同thread / 再送なし。DNS、OS設定、外部network、実WAN loss、再送、MTU、輻輳、本番認証は未実行。Subject/Atlas全体の完成は主張しません。

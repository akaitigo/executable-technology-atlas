# Atlas：新しく開く権限と、開いたファイルを読む権限

この教材では、ディレクトリから新しいファイルへ渡せる権限と、すでに開いたファイル自身の権限を分けて考えます。[学習画面](index.html) は固定 Node で保存した実測を読む入口です。4条件の実測を接続しました。幅1280/390の画面で4条件の権限・40呼出しの値と、読取拒否や回復を確認し、画像を保存しました。範囲は [画面確認](GUI-QA.md) にあります。

FD は、開いた資源を指す番号です。`base` はその FD 自身で許される操作、`inheriting` はそこから新しく開く FD へ渡せる操作を表します。FD_READ は読取り、PATH_OPEN はパスからファイルを開く操作の権限です。

## 予想する

自分で用意した `note.txt` には `Atlas` と改行、計6バイトが入っています。まずファイルを開き、その後ディレクトリの inheriting から FD_READ だけを外すと、すでに開いたファイルも読めなくなるでしょうか。新しい open と、既存 FD の read を別々に予想してください。

## 操作と比較

画面で4条件のいずれかを選び、予想してから記録を開きます。変更のない条件、open 前にディレクトリ側を変える条件、open 後にファイル自身を変える条件、open 後にディレクトリ側だけを変える条件を対照します。

| 条件 | 実装前に固定した期待 |
|---|---|
| 変更なし | open 成功、6バイトの read、その後に EOF |
| 新しく開く権限を先に減らす | open は NOTCAPABLE 76、ファイルの read は未到達 |
| 開いたファイルの権限を減らす | open は成功、その FD の read は NOTCAPABLE 76 |
| 先に開いてからディレクトリ側を変える | 既存 FD の read は成功。変更後の新しい open は NOTCAPABLE 76 |

この期待は実装前の [固定した手表](hand-oracle.json) です。その後の4条件の実測は期待と一致しました。拒否された read の返却バイト数は無効です。成功した read が0バイトを返す EOF と混同しません。

## 原典と実装を確かめる

[原典の対応表](SOURCE-MAP.md) は公式 preview1 の型と uvwasi v0.0.23 の実装へつながります。open が検査するディレクトリの base / inheriting と、read が検査するファイル自身の base を確認してください。Node 25.2.1 と uvwasi 0.0.23 に固定しています。

`module.wasm` は前教材と同じ610バイトです。7つの WASI 関数を実際に呼ぶ小さな Wasm で、`module-contract.json` の型・命令・メモリー配置と別方式の解読で照合します。JavaScript の記録にある引数は教材の Wasm 関数へ渡す引数です。WASI の引数全体は固定引数を含む命令列で確認します。JavaScript がファイル本文を読み、その値を WASI の観測として表示することはしません。

## 答え合わせと実務判断

ディレクトリの inheriting は、新しい FD へ要求する権限の上限です。今回の固定実装では、先に開いたファイルは自身の権限を持つため、ディレクトリ側の変更だけで同じ変更が自動的に伝わるとは扱いません。既存 FD を読めなくする比較では、そのファイル自身の base から FD_READ を外します。

この結果から、Node を安全な隔離環境として採用する判断はできません。[Node の公式 Security](https://nodejs.org/download/release/v25.2.1/docs/api/wasi.html#security) は安全なファイルシステム隔離を保証していません。信頼できないプログラムを扱う設計には別の根拠と環境が必要です。

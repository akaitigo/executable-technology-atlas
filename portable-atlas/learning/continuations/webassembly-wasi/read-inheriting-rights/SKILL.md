# Atlas：WASI の読取り権限を比較する

まず `status.json` を確認する。実測未済なら手表を実測として提示しない。実測が接続済みなら `index.html` を開く案内と、必要に応じて保存記録への読取経路を使う。この Skill を読んだだけで新しい Node、ブラウザー、サーバーを起動しない。

1. 「ディレクトリ側に FD_READ がないとファイルは読めないか」には、base と inheriting の対象の違いを説明する。`directory-before-open` の open が必要とする権限、未到達の read、errno 76 と無効な出力を順に示す。前教材の PATH_OPEN 不足と同じ変更だとは説明しない。
2. 「開けたのに読めないのはなぜか」には、`file-read-reduced` を使う。返却された FD の base が2から0に変わり、その FD の read が拒否されることを示す。nread が無効な null である場合、EOF の0バイトとは扱わない。
3. 「ディレクトリの権限を減らせば既存ファイルも読めなくなるか」には、`opened-before-directory-change` を使う。既存 FD の権限前後、6バイトと EOF、新しい open の拒否を別に説明する。全ランタイム共通の取消し保証へ広げない。

どの案内も、予想→保存実測の操作→成功・拒否・未到達の比較→`SOURCE-MAP.md` と `module-contract.json`→答え→実務上の限界の順に進める。画面で予想や条件を変えたら、過去の結果と答えが消えることを確認する。記録の欠落・改変・別条件による読取エラーは、実際の WASI の権限拒否とは分ける。

信頼できない Wasm を安全に動かす目的なら、Node が安全なファイルシステム隔離を保証しない公式の制限を示す。この教材だけで安全性を認定せず、追加の設計根拠を求める。新しい実験が必要なら元の専有実行枠と負荷・優先度・回収条件を守り、他プロセスを停止したり OS 設定を変えたりしない。

画面の案内では [Atlas の画面確認記録](GUI-QA.md) を参照し、実際に確認した条件と残る制限を伝える。過去の計算結果を、新たに計測した結果として扱わない。

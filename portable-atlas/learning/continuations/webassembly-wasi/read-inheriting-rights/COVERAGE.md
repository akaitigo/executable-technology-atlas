# Atlas：この教材で分かる範囲

分野目標22と `../wasi-preopen-rights/COVERAGE.md:20` の未対応事項を引き継ぎます。前教材はディレクトリの PATH_OPEN、preopen 不在、許可内のファイル欠落を比較しました。ここでは FD_READ の対象がディレクトリの inheriting か、開いたファイルの base かによって違うことを新しく扱います。

| 問い | 固定した比較 | 現在の証拠 |
|---|---|---|
| 新しいファイルへ読取り権限を渡せるか | dir inheriting の FD_READ だけを減らす | 契約・手表・公式実装と、4条件40呼出しの保存実測 |
| 開いたファイル自身を読めるか | file base を2から0へ減らす | 同上 |
| dir の変更が既存 file へ自動的に伝わるか | file を先に開き、変更前後の権限・read・新しい open を別々に見る | 同上 |
| 拒否と EOF は同じか | errno 76 の無効出力と、errno 0 / nread 0 の有効な EOF | 同上 |
| 保存記録が欠けたり別条件に変わったとき | 読取拒否、古い結果・答えの消去 | 隔離された JavaScript 環境で47状態項目。実DOM・実操作による消去・拒否・回復も別途確認 |

実行前に手表と独立期待を固定しています。[保存値の確認](observations/runtime-verification.json) は型・命令の別解読、全イベントと権限差分、返却 FD の接続、回収記録を照合しています。画面へ渡したデータは保存実測の値です。別担当による保存値・Skill の3つの案内の確認と、実DOM・操作・画像の記録、最終独立受入を分けます。詳しくは [画面確認](GUI-QA.md) を参照してください。実測前の期待を実測として扱いません。

次に残る問いは、異なる資源を開く複数の preopen とその選択、あるいは操作ごとの追加権限です。次教材を選ぶ際には既存教材と重複を照合し、実装と安全な前提が揃う問いを一つだけ固定します。権限増加や一般的な取消し保証は今回の結果から推測しません。

# Atlas：AST と stack 命令の保存結果を案内する

## Atlas の適用範囲

非負整数、加算、乗算、括弧の5正常式と7不正 VM 入力だけを扱う。[契約](CONTRACT.md)・[入力](inputs.json)・[固定期待](expected.json)を先に読む。一般のコンパイラ実装、任意構文や任意 AST、変数・関数・型・最適化・JIT・GC・性能の保証まで広げない。支持する問いと範囲外の問いが混ざる場合、狭い保存事実と不足を分ける。専用 Router の完成や未知の問いへの適合を主張しない。

## Atlas の通常の案内

1. [status.json](status.json) で画面確認と受入の範囲を読む。`browser_start_hold` が true なら、新しいブラウザー・サーバー・前面化を行わない。既に利用できる画面ではREADMEの読む順へ進み、それ以外はテキスト・JSON・コードを案内する。実DOMと画像は実施記録が示す条件だけに限定する。
2. [README](README.md) の前提へ戻り、利用者に値だけでなく途中の stack を予想してもらう。自由記述を自動採点したとは言わない。
3. `observation` が null なら実測なしを明示して契約・手計算・原典までで止める。実在する場合、状態が示す実行記録の hash と完全性を確認する。データ欠落や照合不一致を、VM の意図した拒否や値0へ読み替えない。
4. 条件 id を [実行記録](observations/attempt-20261006T180030750576Z/run.json) の `records` から選び、正常は `ast` / `compiled` / `tree_trace` / `vm.trace` を順に読む。不正条件は AST を作ったことにせず、直接渡した `constants` / `code` と拒否時点を読む。
5. [手計算](HAND_TRACE.md)・[原典の対応](SOURCES.md)・[変換器と VM](compiler_vm.py) に戻る。定数表の index と値、命令が持つ引数と演算に使う stack の2値、命令番号と文字範囲を区別する。
6. 最終値と途中の対応を別々に答え合わせし、[COVERAGE](COVERAGE.md) の未対応を明示する。予想を変えた場合は以前の答えを新しい予想への検証として再利用しない。

## Atlas の例と境界

- `2 + 2 * 2`：定数表は値2の1件だが、CONST は3命令。保存した命令と3回の push を示す。
- 括弧：Group 自身の命令がなくても、子の関係が変わるため命令順が変わる。
- 値0と空：`0` は正常値。空の命令列は終端 stack の形が不正で値なし。
- 負 index：Python list の末尾参照を許可せず、VM の契約で拒否する。
- 「値が合えば最適化も正しいか」：今回の値一致だけでは言えない。命令の出所と順序の検査はあるが、最適化を実装・実測していない。

## Atlas の再検査と新規実験を分ける

保存結果だけの検査は、教材ディレクトリで次を使う。producer は起動しない。

```sh
python3 -B verify.py --run observations/attempt-20261006T180030750576Z/run.json --mutations
```

新しい測定は説明に不要で、自動で開始しない。再実行を行う場合は、契約の排他調整、正式な資源読取り、load/CPU/メモリ余裕、nice 実値の確認、CPU/経過時間上限、自己所有子の回収を満たす。読取不明を競合0へ変えない。既存の記録・期待値を上書きせず、新しい試行へ完全出力と失敗を残す。OS設定や依存を変更しない。

この Skill 文書の配置と、別 Agent が未知の質問を正しく案内できることは別です。有限の保存資料読取りが確認されても、一般的な案内評価の完了とは呼びません。

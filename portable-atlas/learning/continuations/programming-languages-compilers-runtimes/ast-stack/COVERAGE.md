# Atlas：今回の範囲と前後の学習経路



|範囲|今回の扱い|確認できるもの・限界|
|---|---|---|
|文字列→token→AST、木の評価|既存前提を再利用|[元コードの完全一致コピー](inputs/prerequisite-language.py)、[出所と hash](records/input-provenance.json)。解析器そのものの新しい完成件数ではない|
|左→右の後順と node 対応|正常5式で新しい実測|全24 node の範囲、全23命令の出所と順序。可換演算の値一致だけで済ませない|
|Group と定数表|正常5式で新しい実測|Group の命令なし、初出値による定数登録と同じ index の再使用|
|木評価と VM の値|別経路で照合|木評価は AST を再帰的に読む。VM は定数と命令だけを読む。Python や入力は共有する|
|命令ごとの stack|保存結果あり|直前/直後、right→left の取出し、最大高。命令番号は byte offset ではない|
|不正 VM 入力|固定7拒否を実測|負/上限外 index、ADD/MUL の値不足、終端0/2要素、未知命令。任意 schema の全境界ではない|
|画面と説明図|固定12条件の画面操作を確認|主要57時点の実DOM、1280/390の撮影。取得失敗・古い応答・消去も検査。[記録と範囲](GUI_VERIFICATION.md)へ|
|限定 Skill|[手順](SKILL.md)を用意|保存資料の有限な読取と、一般 Agent の案内能力の評価を区別する|
|名前解決・GC・Tiny8|既存別教材|今回の新しい成果として加算しない|
|正式統合・分野全体の網羅|未実施|元 owner の現在状態は未確認。小言語の成功で分野全体を完了としない|

Atlas の次の問いは、変数・型・関数・制御の分岐を命令へ下ろすと対応関係や stack の検査がどう変わるかです。非可換演算や副作用の順序、最適化前後の意味保存、機械語・ABI・JIT・GC・性能は別の契約と証拠が必要です。

今回の実装はこの独立ディレクトリだけです。実験・画面・別担当確認の現在状態は [status.json](status.json) へ戻ります。

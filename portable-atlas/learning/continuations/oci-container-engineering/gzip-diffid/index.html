同じ tar なのに、digest が変わる？

圧縮した blob を指すハッシュと、展開後の tar 全体を指す DiffID。その違いを、小さい計算結果で追います。

この画面は保存した Python の計算結果を選んで読むものです。操作で gzip 処理や container を実行しません。図は保存値による説明図です。この保存結果を読む画面の操作と画像は確認済みです。受入状況は末尾の確認状態から辿れます。

前提：非圧縮 tar と descriptor · 元の学習経路 · 関連：opaque whiteout

1. どこまで進むか予想する

descriptor は圧縮 blob の size と digest、DiffID は非圧縮 tar 全体の digest です。期待する値は信頼できる場所から得た、と仮定します。

保存結果を読み込みます。

2. 同じ tar を二つの gzip で包む

この対照では gzip header の offset 4 が 0 → 1 に変わりました。tar 側の時刻は 0 のままです。すべての圧縮器・version で同じ blob になる、という保証ではありません。

    5. 答えと実務の判断
    圧縮 blob の一致は、その blob の内容が期待どおりであることの確認です。別の内容から作った blob と descriptor が互いに一致しても、元の DiffID と一致するとは限りません。期待値そのものが攻撃者に差し替えられる場合の認証は、この模型では扱いません。
    連結 member は gzip の仕様で認められます。今回は単一 member だけを読む有限契約のため拒否しています。tar の検証・host への適用、展開爆弾全般の防御、署名、registry、container 起動、zstd、OCI 全適合の証明は対象外です。

装置を忘れたsnapshot

PCとメモリーが戻っても、続きは同じでしょうか。

周期3の小タイマーを含む状態で、継続・完全復元・装置欠落を比べます。仮想tickだけの有限模型で、実VMや物理時間の測定ではありません。

1. 前提と順序

counterは発火までの進み具合、pendingはACKまで残る保留、ACKは保留を消す命令です。READはpendingをAへ読むだけで消しません。

  1. tickを進める
  2. timer更新・発火
  3. 命令を実行
  4. pcを進めて保存境界へ

tick6は発火してからACK。命令途中の保存と割込みハンドラーの自動実行はありません。

2. 条件を選んで予想

切断点は命令の完了後です。ボタンをクリックして条件を確定します。

deviceだけを省略して0,falseへ戻すと、suffix全状態は継続と一致しますか？ pc/A/memory/tickは保持します。

保存記録の読取り条件

保存データの複製を変える表示検査です。実ネットワーク障害や外部攻撃の測定ではありません。

3. 同じ保存地点から続きを比べる

prefixは保存地点まで、suffixはその後の続きです。

カードは選択中の境界。発火・READ・書込みはその境界を作った直前の1命令です。切断点ではまだsuffix命令を実行していません。

全suffixの保留状態

横にスクロールできます。各経路の上側の点はpending=true、下側はfalse、数字はcounterです。点は命令完了時点の保存値で、線は読み順の目安です。物理時間の波形ではありません。

4. 原典・実装を読み、答え合わせ
契約・手計算・実装を読んでから答えを開きます。


5. 実務判断と限界
成功した切断点だけで必要な保存欄が揃ったとは判断できません。正常restoreの欠落拒否と、別schemaの意図故障を分けます。形式のhashはbyte対応で、認証や互換性の証明ではありません。
実QEMU/HVF、実VM、隔離、物理時間、live migration、任意のプログラムは未検証です。前提のTiny8幅・STORE原理は今回の追加成果へ数えません。

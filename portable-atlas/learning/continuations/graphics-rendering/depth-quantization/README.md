# Atlas — 奥行きを丸めると、手前の面が残るとは限らない

二つの面が同じ描画標本を覆っていて、Aの奥行きは2/5、Bは7/15です。Aが手前でも、保存時に両方を同じ整数へ丸めると、描画順で残る面が変わります。この教材では、丸める前の比較、保存する整数、残る面を一段ずつ分けます。

## 最初に読むもの

[画面を開く](index.html) → 予想を選ぶ → 保存した計算を開く → 描画前と各描画後を比べる → 原典と実装を読む → 答えを照合する、の順です。ファイルを直接開いても画面コードは読めます。ローカル配信を使う場合は、このディレクトリで既存Pythonの `python3 -B serve.py --port 0` を実行し、表示された `ATLAS_PORT` の `http://127.0.0.1:番号/` を開きます。この配信は計算を実行しません。制作中の実計算・画面確認の状態は [status.json](status.json) を参照してください。

前提は [前提を読む順](PREREQUISITES.md) にまとめました。同じ標本を覆うかどうかの判定、厳密な奥行き比較、clip、透視補間は既存教材へ戻れます。ここではそれらを再計算しません。[限定Skill](skills/atlas-graphics-depth-quantization/SKILL.md) は、問いから比較条件と根拠へ案内します。

## 何を比較するか

zは投影後の正規化された奥行きで、0から1、小さい値ほど手前です。整数保存方式は `M=2^b−1`、`Q(z)=floor(Mz+1/2)` とします。非負の半分は大きい整数へ丸める、教材独自の規約です。実GPUの丸めを再現したものではありません。

両方式とも初期値は最大値、更新条件は「入ってきた値が保存値より小さい」です。等しい場合は更新しません。

| 対照 | 判断できること |
|---|---|
| 3bit、A→BとB→A | 厳密値は異なっていても、両方3へ丸まると先に描いた面が残る |
| 4bit、同じ二つの順序 | この入力では6と7へ分かれ、Aが残る |
| 真に同じ奥行き、二つの順序 | 丸めがなくても厳密な小なり比較は先勝ちになる |
| 0、半分の前・一致・後 | 丸めの境界と比較の規則を別に読める |
| 31/32と1 | 1未満でも最大整数へ丸まれば背景を更新しない。z=1は厳密方式でも更新しない |

中心6条件と別標本の12境界です。「4bitにすればいつでも解決する」という一般化はできません。

## 原典、手計算、実装

[MicrosoftのDepth Buffers](https://learn.microsoft.com/en-us/windows/win32/direct3d9/depth-buffers) は、奥行きの保存と比較、最大値での初期化、比較関数が設定できることの根拠です。本教材の3/4bit整数化や半分の規約はそのページのGPU仕様ではありません。[根拠と独自規約の対応](SOURCE-MAP.md) を先に区別してください。

[有限契約](CONTRACT.md) と [手計算の説明](HAND-CALCULATION.md)、[固定手期待](hand-oracle.json) は実装前に保存しました。[計算の実装](model.py) は商余りで丸めます。[保存結果の検査](verify.py) は模型を呼ばず、固定手表の全値と半開区間への所属を照合します。区間の右端は含まず、許容域端のz=1は最大区間に含みます。区間に入ることと描画に採用されることは別です。

## 保存結果から再確認する

保存済みの結果は `python3 -B verify.py observations/calculation-20261007T010837369691Z` で照合できます。これは保存結果の読取りで、GPUや計算模型を再実行しません。[計算結果と確認範囲](CLI-RESULTS.md) に実行ログ、標準出力・標準エラー、使用コードのhash、実nice値、子の回収記録をまとめています。

今回の1回では6中心条件・12境界の24描画、48比較、入力拒否20件が固定手表と一致しました。保存値の変更16件も検出しました。画面はこの保存値を読む構成で、画面の期待コピー自体を独立手計算とは呼びません。

実画面では18条件・42固有段階の表示と操作、6資料へのクリック、1280/390幅の14画像を確認しました。[画面確認の範囲と画像の限界](GUI-QA.md) に、DOMで読んだ値と画像に写った部分を分けて記録しています。独立受入の最新状態は status.json に従います。

新しい計算は `run.py --record --gate …` の明示指定と直前の資源条件が必要です。既存Pythonの単一子、nice10、5秒上限と別回収2秒、自動再試行なしを使います。過去の資源許可は引き継ぎません。

## 実務で次に確認すること

描画順依存を見つけたら、まず元の奥行きが同じなのか、保存後に同じ値になるのか、最大値と比較しているのかを切り分けます。実製品なら、使うdepth形式、比較関数、初期値、投影とnear/far設定、対象GPUの観測が別途必要です。

ここでの実行は有理数と整数の有限模型です。実GPU、実API、画面のちらつき、driver、浮動小数点depth、reversed-Z、MSAA、透過、性能を測定していません。画面は保存した計算の説明用で、新しい描画装置の観測ではありません。

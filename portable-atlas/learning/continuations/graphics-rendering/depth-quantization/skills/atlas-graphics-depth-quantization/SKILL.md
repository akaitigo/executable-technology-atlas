# Atlas — 奥行き保存の問いを有限比較へつなぐ

入口は [README](../../README.md)、操作は [学習画面](../../index.html)、前提は [読む順](../../PREREQUISITES.md) です。保存計算と実GPU測定を区別して案内します。

1. 「手前のAが残らないのはなぜ」には3bitのA→B/B→Aを比べます。A=2/5、B=7/15を保ったまま保存整数が3/3になることを、比較前後の表で示します。B→Aで厳密方式はA、整数方式はBです。
2. 「4bitなら解決するか」には同じ入力の4bit二条件を使います。6/7へ分かれるのでこの入力ではAになります。全深度・全GPUでの解決とは答えません。
3. 「先勝ちは全部丸めのせいか」には真の同値二条件へ進みます。厳密方式も同値を更新しないので描画順に依存します。
4. 「ちょうど半分はどうなるか」には3/4bitそれぞれの49/100、1/2、51/100を読みます。[手計算](../../HAND-CALCULATION.md) の区間所属と描画採用を分け、Python roundやGPU既定規則と混ぜません。
5. 「zが1未満なら必ず描けるか」には31/32と1を比べます。31/32は厳密方式だけ採用、1は両方式とも背景です。最大整数へ丸まることと、厳密に1であることを区別します。
6. 「実製品のちらつきもこれで証明できるか」には [範囲](../../COVERAGE.md) と原典へ戻します。実GPU観測は0、独自丸め式の有限反例です。投影・形式・比較関数・初期値・実測が追加で必要です。

予想変更や条件変更で古い答えを使い回しません。保存結果が欠落・変更された表示は根拠にせず、正常記録へ戻して開き直します。[固定手期待](../../hand-oracle.json) と [保存検査](../../verify.py) は別方式の照合で、画面の期待コピー自体を独立証明とは呼びません。

# Atlas — ヒストグラムから分位点をどこまで読めるか

## 今回の問いと前提

目標53の「調査に必要な証拠・費用・保持範囲」を、記録する粒度の判断へつなぎます。既存の [collector 教材](related.html?doc=collector) の生データ nearest-rank・欠落・遅着は前提です。今回は全件既知の架空の待ち時間を区間ごとの件数へまとめ、元の値と、残った区間と、仮定を置く補間値を分けます。実 collector や通信の測定ではありません。

## 固定入力

[cases.json](cases.json) の5列を各 q=0, 1/2, 3/4, 1 で読む20組だけです。単位は架空の ms。整数0〜40、最大8件です。bool は整数として認めません。粗い区切りは [0,10,20,40]、細かい区切りは [0,5,10,15,20,40] だけを認めます。最初の区間は下端と上端を含み、以後は下端を含まず上端を含みます。したがって値10は [0,10] に入ります。件数は区間ごとの値であり、累積件数は別欄です。

| ID | 元の列 | 区切り | 比較する理由 |
|---|---|---|---|
| pair-a | 1,2,11,12 | 粗い | 元の値が区間の低い側にある |
| pair-b | 8,9,18,19 | 粗い | pair-a と同じ区間件数でも元の分位点は異なる |
| finer-a | 1,2,11,12 | 細かい | 同じ列を細かい区間で保存する |
| boundary | 0,10,20,40 | 粗い | 値が区切りに一致する |
| empty | 空 | 粗い | 分位点を0に置き換えない |

## 生データと集約側を分ける

生データの答え合わせは昇順で、q>0 は1始まりの順位 ceil(q*n)、q=0 は最小値（順位1）です。偶数件の中央値を中央2値の平均にはしません。

集約側の関数に渡すのは区切り・区間件数・qだけです。case ID、元の列、最小/最大値、元の分位点を渡しません。合計件数 n は件数の和です。n>0, q>0 なら累積件数が q*n 以上になる最初の非空区間を選び、q=0 は最初の非空区間を選びます。この区間は元の nearest-rank 値が入る場所であり、確率的な信頼区間ではありません。

選んだ区間の下端L、上端U、前までの累積件数B、その区間の件数Cから、教材の補間値を L+(U-L)*(q*n-B)/C とします。q=0 は最初の非空区間のL、q=1 は最後の非空区間のUです。両端も元の最小/最大を復元した値ではありません。区間内を均等に進むという仮定を置いた数値で、観測された値ではありません。端点の推定値が開区間の下端になる場合も、元の値の候補と同一視しません。

計算は Fraction で正確に行い、分数文字列を保存します。図で小数へ変換するのは位置の表示だけです。空列は件数0、順位・選択区間・生の分位点・補間値・誤差をすべて null とし、状態 empty を返します。

## 比較と検査

実装前の [手計算表](expected.json) を固定します。作者の検査は関数を再利用せず全20行を literal 表へ照合し、別担当も実装を読む前に独立表を保存します。入力の前後を型込みで照合し、集約関数に元の列が入らないことを引数と保存入力で確認します。pair-a/pair-b の集約入力・集約出力は同一、生の分位点は異なります。finer-a は同じ列に対する区間幅の縮小を示しますが、細分化が任意分布で誤差を必ず改善するとはしません。

保存結果の欠落、件数/境界/分数/元の値/空状態の改変を有限に拒否します。入力検査は実装に持ちますが、不正 schema の実行網羅は今回行いません。保存結果を開く画面では欠落・改変・取得失敗と遅い旧応答で古い図/答え/実装を消すことを別に確認します。

## 実行と限界

既存 Python 標準ライブラリの小さい有限計算です。実行は資源確認後の単独枠、実優先度 nice>=10、1子・約5秒以内・自動再試行なしを外側の実行器で管理します。今は未実行です。画面は保存した計算結果を読み、操作のたびに実 collector を動かしません。

この有限区間・補間式・端点処理は Atlas 教材独自の規約です。Prometheus/OTel の製品適合や histogram_quantile の再実装を主張しません。OTel の全データモデル、sketch、実 collector、SLO/alert、計測性能、任意分布の誤差保証、欠測補正は範囲外です。

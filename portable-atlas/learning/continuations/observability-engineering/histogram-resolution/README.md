# Atlas — 同じヒストグラムなら、分位点も同じ？

待ち時間を一件ずつ残す代わりに、区間ごとの件数だけ残すと何が分かるでしょう。[学習画面](index.html)では、同じ件数になる異なる2列と、区切りを細かくした列を比較します。元の分位点、所属する区間、仮定を置いた補間値は別の情報です。

前提は [計装の基礎](related.html?doc=base) と [欠落・遅着と生データ分位点](related.html?doc=collector) です。後者の nearest-rank（指定順位の実際の値）を使って答え合わせをします。今回は全件が分かっている架空の待ち時間を集約する小さな計算です。実サービスの待ち時間や collector の測定ではありません。

## 読む順

1. 条件と q（分位点の位置）を選び、補間値が元の値より大きいかを予想する。
2. 保存した結果を開き、区間件数・累積件数・選択区間を読む。
3. 同じ件数になる A/B と、細かい区間の A を比較する。
4. [原典と規約](SOURCES.md)、[実装](histogram.py)、[実行の方法](REPRODUCE.md) へ戻る。
5. 答えと、必要な情報を何として保存するかを考える。[Skill](SKILL.md) に3つの問いがあります。

q=1/2 は偶数件でも中央2値の平均にしません。今回の q=0 は生データ側では最小値、補間側では最初の非空区間の下端です。後者を実測の最小値と呼びません。空は「未定義」であり0msではありません。

## 画面を開く

このディレクトリで `python3 -B serve.py --port 0` を実行し、表示された `ATLAS_PORT` の値を使って `http://127.0.0.1:番号/` を開きます。保存結果と資料だけを配信します。終了はそのサーバーへ Ctrl+C。これは再現手順で、制作中に作者がサーバーを起動したという記録ではありません。

固定5列×4分位点の [計算結果](observations/run-01/results.json) を1回保存しました。[保存値の検査](observations/run-01/saved-result-check.json) は161関係・8改変を確認しています。実画面でも20組、13の切替状態、5つの取得失敗・古い応答を確認し、1280px/390pxの9画像を保存しました。最終独立受入の状態は下記へ結びます。[確認状態](qa/reader-acceptance.json) で現在の範囲を区別します。CONTRACTは実装前に固定した計画の記録として保持しています。

ヒストグラムから元の列を復元しません。今回の補間は独自規約で、Prometheus/OTel の製品適合、任意分布での誤差保証、SLO/alert、保存費用の実測は行いません。[範囲](COVERAGE.md) と [既存教材との対応](reuse-and-scope.md) を参照してください。

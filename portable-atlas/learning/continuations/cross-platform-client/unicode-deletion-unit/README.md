# Atlas｜末尾の「1文字」を、どの単位で消す？

同じ見た目でも、末尾を一つ消した後に残る列は同じとは限りません。正規化する時点と、削除単位を別に決める必要があります。この教材は7固定要求をUTF-16単位・scalar・拡張書記素クラスタ（EGC）の3方式で比べます。

読む順は、[既存のJS/Python契約](related.html?topic=base)→[SwiftのCharacterとwire単位](related.html?topic=swift)→[今回の学習画面](index.html)→[限定Skill](SKILL.md)です。元の計数やJSON往復を今回の新実験として数えません。[起動と再現](REPRODUCE.md)、[契約](CONTRACT.md)、[原典対応](SOURCES.md)、[範囲](COVERAGE.md)へ戻れます。

画面では条件と予想を選び、保存した削除結果を再生します。`Ae + U+0301` のscalar削除が `Ae` を残す一方、EGC削除では `A` が残る予想から始めます。先にNFCへ正規化した条件とも比べ、NFCが削除単位の指定そのものではないことを確かめます。

`A😀` とZWJでつながるemojiでは、UTF-16の1コード単位を削ると孤立surrogateが残る場合があります。その診断を文字列として描画せず、コード単位列とscalar-valid=false、UTF8=nullで示します。置換文字へ直した結果を実測に混ぜません。

今回のアプリは末尾1 EGCを削除する方針です。全てのOSのBackspaceやIMEが同じ動作をすべきだという意味ではありません。実務では編集単位と正規化時点を先に契約にし、通信・保存のbyte制限とは分けます。

7要求・21結果と拒否6例を、Node 25.2.1／ICU 78.1／Unicode 17.0で計算しました。[保存結果](observations/run-01/results.json)と[照合記録](verification/saved-result-check.json)では、実装前の固定表への436項目と7種類の改変検出を確認できます。別担当の独立照合はこの件数へ足しません。

原典はUAX #29 rev43（Unicode 15.1）とUAX #15 rev58（Unicode 18.0）です。実行版と同じ版とは扱いません。今回の結合文字・既存のemoji ZWJ列に限って、固定した境界と正規化の期待を実APIへ照合しています。全Unicodeや版間の互換性を保証しません。

# Atlas｜実行可能でも、空きを待つ

同じDAGでも、「親の仕事が終わっていない」と「親は終わったがworkerが埋まっている」では、待ちを減らす判断が変わります。この教材ではA→B/C→Dの4仕事を仮想時刻で計算し、容量1/2と、開始を完了扱いする故障を比べます。

最初は[学習画面](index.html)を開きます。HTTPでの起動方法は[再現手順](REPRODUCE.md)、現在の確認範囲は[確認状態](qa/reader-acceptance.json)にあります。保存結果を読む画面なので、ボタンを押しても実workerやPython計算は起動しません。

## 読む順と前提

1. [既存の逐次DAG](related.html?topic=dag)で、依存・開始・成功/失敗・retryを確認する。
2. [依存のない仕事と容量](related.html?topic=queue)、[優先順と待ち](related.html?topic=priority)で、枠が埋まると待ちが生まれることを確認する。
3. この画面で「依存を満たした仕事の集合」と「今すぐ始められる数」を分ける。
4. [限定Skill](SKILL.md)から、判断したい場面を保存値・原典・範囲へ結び付ける。

既存runnerの `topology()` は順序を決め、`run()` は順に同期実行しretry/再利用を扱います。今回の追加はworker容量と仮想開始・終了時刻です。既存の逐次DAGや性能教材を未教材扱いせず、共通原理は前提として再利用します。159件の基準からの選定と狭い根拠は[SOURCES.md](SOURCES.md)にあります。作者による教材数の加算は行いません。

## 予想から判断まで

画面で条件と予想を選び、「保存した予定を再生」を押します。容量1のt=1では、Cは解放済みの空き待ち、Dは依存待ちです。容量2のt=3では、空き1枠があってもDはBを待ちます。容量を増やすだけで全ての待ちを取り除けるわけではありません。

故障比較では開始時に `done()` を通知します。BはAの終了前、DはBの終了前に始まります。t=3ではgraphlibが処理済みでもBとDはまだ実行中です。全仕事の終了まで追い、終了時刻4という短さを有効な高速化と取り違えないようにします。

同時終了の対照はBの所要時間を2へ変えます。B/Cの両終了を処理した後、同じt=3でDを開始します。半開区間とID順の規則は[先に固定した契約](CONTRACT.md)、4条件18境界の予想は[手予定表](expected.json)で確認できます。

対照を読んだら、原典・保存時の実装・答え合わせへ進みます。予想や条件を変えると前の結果を消します。読込失敗・改変でも、前の予定や答えを残しません。図は保存した仮想時刻から描く説明図で、実並列処理の映像ではありません。

# Atlas：実装前の手計算と問い

以下は実測ではなく、実装前に固定した期待です。完全な陽性 ID 集合・追加 ID・件数・約分した分数は [expected.json](expected.json) にあります。

元20件の降順は `p01 .80 → n01 .70 → n02 .40 → p02 .35 → n03 .25 → … → n18 .02`。閾値を下げると、この順で陽性 ID 集合が広がります。陽性2件と陰性18件の分母は途中で変わりません。

|条件|陽性 ID|TP/FP/FN/TN|Recall|FPR|Precision|
|---|---|---|---|---|---|
|最大より上|空|0/0/2/18|0|0|未定義 0/0|
|0.80以上|p01|1/0/1/18|1/2|0|1|
|0.40以上|p01,n01,n02|1/2/1/16|1/2|1/9|1/3|
|0.35以上|上記＋p02|2/2/0/16|1|1/9|1/2|
|0.02以上|全20件|2/18/0/0|1|1|1/10|

0.40→0.35では本当の陽性だけが1件追加され、Precision は増えます。陽性 ID 集合の包含関係と、Precision の単調性は同じ話ではありません。

Atlas の別の同点対照は `t-high .90` が陽性、`.50` の `t-positive` が陽性、`t-negative` が陰性です。0.50以上では同点2件が同時に加わります。高得点陽性と同点陽性だけを選ぶ中間状態は、この閾値規則では作れません。

ROC の全陰性端点は (0,0) です。同じ条件の PR は Precision が未定義なので、(0,0) や (0,1) として描きません。この契約では AUC を計算せず、点を結ぶ線も面積や実現可能な中間閾値の保証に使いません。

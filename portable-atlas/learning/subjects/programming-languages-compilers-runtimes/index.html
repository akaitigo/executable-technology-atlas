    03
    Grammarと境界を確認する
    小さいgrammar
    expr := term ('+' term)*
term := atom ('*' atom)*
atom := INT | '(' expr ')'
INT  := ASCII [0-9]{1,6}
    同順位は左結合。括弧は内側のexprを先に組む。tokenだけでは演算のまとまりは決まらず、parserが構造を作る。
    入力errorは評価しない
    任意コードの実行はしない。`eval()`、`exec()`、host言語ASTは不使用。未対応文字、operand欠落、括弧欠落は停止する。
    256 code point、整数6桁、括弧depth16まで。負数、変数、関数、`/`、floatは未対応。offsetは0始まり・line/columnは1始まりで、byte offsetではない。

    05
    答え：parserが「まとまり」を作る
    正常ASTは 2 + (3 * 4)。3と4を掛けた12を、2へ足して14になる。naiveは (2 + 3) * 4 という別の木を作り20になる。文字列を読み終えたことと、期待grammarのASTを作れたことは別だ。
    括弧を付けた (2 + 3) * 4 では両grammarの木と結果がそろう。error位置は最初に違反を検出した点で、修正原因や作者の意図をすべて推定したわけではない。壊れたinputを0として評価せず、値を出さない。

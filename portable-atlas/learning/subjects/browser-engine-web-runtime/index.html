microtaskは、いつ処理される？

同期log、Promise、microtask内の追加microtask、timer内のmicrotaskを実Browserの順序で比べる。

有限3caseの一教材。engine内部・全Browser・timer精度の保証ではありません。

学習の道筋

前提: 関数呼出し、Promise.then/catch、setTimeout、try/throw、配列を読めること。

概念と仕組み: 同期呼出しは最後まで進む → Promise reactionをmicrotaskとして処理 → checkpointで追加分も処理 → 後続timer task → その中で追加したmicrotask。Browserのtask選択とECMAScriptのPromise jobを分ける。

今回: 予想→別Documentで操作→基本/追加/例外の実trace比較→誤モデルとの差→実装と原典→回答。

実務判断: Promiseへ移しただけでは必ずtimerや描画へ制御を渡せるわけではない。catchも後続reactionとして確認する。delay 0を即時実行や締切保証に使わない。

限界: 同一origin iframeは新Documentだが専用thread/processやsecurity sandboxではない。traceはこのcallbackのinstrumentationで、Browser全体のscheduler/Network/paint traceではない。次の4実験へ。

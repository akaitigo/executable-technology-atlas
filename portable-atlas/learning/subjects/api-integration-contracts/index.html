01 — 契約を読んで、予想する

このAPIは200＋application/json、必須id（integer≥1）/name（空でないstring）。noteはoptional string、他fieldは許容。422はerror.code/messageを確認してエラー処理へ。これは固定手書き規則で、全JSON Schema evaluatorではありません。

03 — 実装とHTTP原典へ
前提はrequest/response、status、header、JSONの値型。200だけでschemaを保証するわけではなく、201はHTTPとして成功でも、このAPIのexact 200契約とは別です。optional追加を許す方針では互換ですが、全clientが追加fieldを許容するとは限りません。
Content-Type原典JSON値型原典固定契約client判定実HTTP runner独立case Oracle実行原票時刻・環境・digest
client timeoutは応答前のsocket待ち上限0.1秒、通常2秒、観測process全体15秒。汎用のend-to-end deadline保証ではありません。timeout時は成功も「serverが処理しなかった」ことも推定しません。今回GETにretryはありません。


04 — 判断と、次の問い
通信失敗／status拒否／media拒否／構文拒否／必須・型拒否／有効なエラー応答を分けて調べられます。型を黙って変換して接続成功にしないこと、互換性はconsumer側の追加field方針にも依存することが今回の判断範囲です。

importは、値のコピーではない

2つのimporterから同じcounterを参照する。live binding、値のコピー、読取専用を別々に観察しよう。

native ES modulesだけの教材。framework/build tool、他runtime、循環依存の網羅検証ではありません。

学習の道筋

前提: let/const、関数呼出し、object property、Promise/try-catchの基本。曖昧なら先にそれぞれ小さな式で確認する。

主要概念: export元のbinding → importerの間接参照 → module URL/Document単位の評価 → HTTP読込とparseの違い。

今回の実装: 予想 → A/B操作 → live/snapshot比較 → 代入拒否と別Document失敗 → Source → 回答。

実務判断: 更新後の現在値を読むならlive参照、特定時点を保持するならコピー。共有moduleの初期化をimporterごとに再実行されるものと設計しない。代入エラーはexport元の更新関数へ、404とSyntaxErrorは読込/構文の別層へ切り分ける。

限界: DOMの再描画はこの教材のrender()が明示的に行う。live bindingだけでUIが自動更新されるわけではない。cycle、framework、build tool、他realm/他runtimeは未教材。次の4実験と原典 / coverage

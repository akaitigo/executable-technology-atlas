同じentity、違う表示？

同じ保存データをlist/detailへコピーする設計と、IDから一つの所有stateを参照する設計を並べる。

native JSの有限一教材。React/Redux/実network/persistence/SSR/routingの実行ではありません。

学習の道筋

前提: object/array、ID、コピーと参照、関数、DOMのtextContentを読めること。

主要概念: entityのidentity → 保存データの所有者 → list/detailの派生表示 → selectionはID → 更新/削除時の不変条件。

今回: 予想→両設計へ同じ編集→不整合比較→選択/削除/unknownID/不正編集→図と実装/原典→回答。

実務判断: 同じ保存データの複数viewでは、更新責任とID参照を整理する。draftは保存データと別概念で、必要ならcopyを持てる。全stateをglobalにする判断とは別。

限界: 正規化だけでnetwork競合、権限、validation全般、全viewの正しさは保証しない。本fixtureは選択UIのIDもモデル内に持つ。次の4実験へ。

認証済みactorを仮定しても、objectごとの権限検査は別です。lookup-onlyの反例と、tenant・operation・resourceを検査するpure handlerの結果を比べます。

この教材の学習の道筋

前提（dict・request/response・架空tenant）→ 認証と認可の分離 → lookupとobject権限の仕組み → 下の正常/異常操作 → 実務で問うcontrol → 限界 → 原典、の順に読みます。

今回から判断できること：lookupだけを許可根拠にしない。同tenantでもoperation/resource grantを問う。trusted identityをclient入力から作らない。拒否bodyにpayloadを残さない。この判断は実製品の安全認定ではありません。

ページ内JSはcomputed nameを推測表示しません。ブラウザのAccessibility treeでrole「button」・name空 →「カウントを増やす」を観察します。読み上げ音声の実測とは別です。

4. 実装と一次資料で理由を確認する

このカウント操作では、可能ならnative buttonを選ぶ。カスタムroleを付けても、キーボード操作は自動追加されない。修正版divはSpaceのkeydownでスクロールを防ぎ、keyupで1回動作し、blurで保留中の操作を取消す。フォーカスは同じ場所に残る。
無効時: native disabledはTab順から外れる。修正版のaria-disabledはTabで到達可能なまま、クリックとキーの動作をコードで拒否する。この違いは不具合と決めつけず、設計条件として扱う。
  • W3C APG Button Pattern — role/name・Enter/Space・動作後フォーカスの設計指針。
  • Accessible Name Computation 1.2 §4.3.2 — 名前計算におけるhiddenと参照の扱い。この例にはaria-labelledby参照はない。
  • ARIA in HTML — native HTMLの暗黙roleとARIA利用条件。
APGは実装の指針であり、教材の試験結果だけでWCAG適合を判定しない。

    03
    束縛と評価は、同じ仕事ではない
    この小さなsemantics
    Int / Var / Let / Fn / Call / Addだけ。Let initializerは外側envで評価し、その結果を新frameへ束縛。Fnはbodyと定義envをClosureとして持つ。Callはfn、argの順に評価し、parameter frameのparentにcaptured envを使う。
    parameterは新しい束縛として近い位置にあり、同名の外側nameをshadowする。argはcallerで評価するので、自由変数の解決場所とは区別する。
    Scope ≠ type system
    lexical/static scopeはnameと宣言の関係。静的型検査ではない。この教材には実行時のnot-callable / addition-type検査だけがあり、型推論やtype safetyの証明は未実装。
    未束縛名は結果なし。正常0とは異なる。AST拒否・Runtime error・64 evaluation budget停止も区別し、budget停止を発散の証明と呼ばない。

    05
    答え：呼ばれる前に、戻る場所を持つ
    fのClosure c0はe1のx=10を持つ環境を参照する。parameter u=0のe4からe1へ探し、10を返す。callerのe3にはx=20があるが、正常なbodyのlookup chainへは入らない。
    誤実装はe4のparentをe3にして20へ解決する。parameter shadow caseなら両方7で、1つの成功例だけでは誤ったparentを見逃す。callerにだけxがあるcaseでは正常はunbound、誤実装だけ20を返す。
    今回から、自由変数の定義位置、parameterの近い束縛、argのcaller評価を分けて調べられる。実装reviewでは「結果」だけでなくcapture/activation parentとlookup chainを見る。今回のframe追加は既存bindingを変更しない。mutation時のcaptureを値snapshotと一般化しない。

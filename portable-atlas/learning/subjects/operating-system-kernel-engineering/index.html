writeを止めたのに、readerが終わらない？

元のwrite FDを閉じても、duplicateが残ればpipeはEOFになりません。実parent/childの観測でresourceの寿命を追います。

前提 → 主要概念・仕組み

FDはprocess内の番号、open file descriptionへの参照。pipeのbufferを読み切り、全write-endをcloseした時にreadは0bytes（EOF）を返します。ready handshakeで起動と同期し、waitでchildを回収。SIGTERM終了はEOF正常完了とは別です。

5. 答え
dupが1つでも残ればwriter参照は0にならず、empty pipeのreadは待ち続けます。正常closeはpayloadをdrainしてEOF。leak-releaseはbounded timeout後にdup closeでEOFへ回復。leak-signalはSIGTERMでchild終了、EOFなし。waitしてchildを回収し、残るFDもcloseします。SIGTERMをprotocol正常完了と混同しません。

02 · TRACE THE BOUNDARY

主要概念 / 仕組み

source

同じ commit
outbox
seq / event ID / delta
seq > offset
consumer
effect + inbox commit
その後
checkpoint
最後に適用した seq

出力と inbox は同じ transaction。checkpoint は別 transaction。replay 条件はこの間で実子processを終了させます。Kafka の next-offset や WAL LSN、SQLite の WAL checkpoint とは違う位置の定義です。

    04 · DECIDE
    実務判断 / 限界
    source/event の同一 commit は、通知欠落と phantom の両方を防ぐ出発点です。consumer の offset は出力の一意性を単独では証明しません。同じ sink transaction で ID と出力を保存する、または位置と出力を原子的に保存する設計を比較しましょう。無効 schema で offset を進めるか、停止・隔離するかは別の業務判断です。
    今回の限界：1 aggregate・単一 seq・逐次処理・有限 highwater。ネットワーク、並行 consumer、replication、停電耐久、実 WAL CDC / Kafka / Debezium / Flink は未実行。冪等条件の単一 effect を production exactly-once の証明に使えません。

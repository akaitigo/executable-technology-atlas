02 · READ CAUSALITY

主要概念 / 仕組み

NODE A · local edit

A1 = 20 · [1,0] · wall100
A2 = 21 · [2,0] · wall90

offline outbox
→ reconnect →
NODE B · local edit

B1 = 30 · [0,1] · wall80
同時更新は比較不能

[2,0] は [1,0] より因果的に新しく、[0,1] とは比較不能。logical mergeは後継21と競合30を保持します。wall-clock maxは古い20だけをheadに残します。両nodeが同じheadでも業務的に正しいとは限りません。

buffer満杯はwrite受入前に拒否。deliver成功/exact duplicateの後だけoutboxから削除。同ID・異なるpayloadは競合として保留します。実disk/ack durabilityは未モデル化。

04 · DECIDE
実務判断 / 限界
offline受入には鮮度・競合・容量の契約が必要です。vectorで競合を保持してもvalue21と30の業務上の解決は別の仕事。wall-clockと収束だけでは因果後継の保持を判断できません。localの速さと全nodeの一致は別の評価軸です。
今回の限界：in-memory 2node model / 固定小schedule / count容量 / 仮定cost。実端末、network、clock同期、disk永続化、reboot、lost ack、security/OTA、real-time制御、resource/energy/熱、外部sinkは未実行。全Subject・全Atlasの完成ではありません。
